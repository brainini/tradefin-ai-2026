# 4일차. 수출채권 회수 전략 최적화 및 조기 경보 시뮬레이션

**10/19(월) 09:00–17:50** · 대전 · 강사 한태구 · AI로 일하는 법 — 최적화 · 시뮬레이션 · 경보 자동화 · 보고서 파이프라인

!!! abstract "오늘 하루 한 줄 — 예측을 한도 · 경보 · 보고로 바꾼다"
    오전에는 정책 문장을 최적화 모델로 옮겨 바이어별 한도를 구하는 법, 평균 하나가 아니라 분포로 쇼크 손실을 읽는 법, 규칙으로 조기경보를 설계하고 GitHub Actions로 자동 실행하는 법, 숫자는 코드가 · 문장은 AI가 · 서명은 사람이 하는 보고서 파이프라인을 시연 다섯 건으로 봅니다.
    오후에는 그 시연을 **작게, 그리고 조금 다르게** 모두가 내 저장소에서 직접 해 봅니다. 하루가 끝나면 **한도안 · 스트레스 표 · 실험 기록, 내 규칙을 더한 경보 워크플로와 자동 이슈, 독자에 맞춘 보고 파일, 내 저장소의 PR 3개**가 남습니다. 저녁 8교시에는 아침에 건 예약 실행이 정말 돌았는지 확인하고, 엑셀 안의 AI를 마지막 시연으로 봅니다.

!!! note "Claude Code는 유료 구독이 필요합니다"
    Claude Code는 Pro 이상 구독이나 API(Console) 계정으로 로그인합니다. 무료(Free) 플랜으로는 쓸 수 없습니다. 설치가 막힌 PC는 내 저장소에서 **Codespaces**를, 계정이 없으면 **채팅 경로**로 같은 실습을 합니다 → [실습 A 채팅 경로](lab-a.md#chat-path) · [실습 B 채팅 경로](lab-b.md#chat-path).

!!! tip "패키지가 없다고 하면"
    오늘 새로 필요할 수 있는 패키지는 **`docxtpl`**(Word 템플릿 — 실습 B ③)입니다. Claude Code가 `uv add docxtpl`을 하겠다고 먼저 알려 주면 읽고 승인하고, 직접 한다면 터미널에서 `uv add docxtpl`. `pyproject.toml`과 `uv.lock`이 함께 바뀌니 커밋에 포함합니다.

## 오늘의 결과물과 제출 {#submit}

오늘 결과물은 **내 저장소의 PR 3개와 그 안의 파일 · 자동으로 생긴 이슈 하나**입니다. 결과 파일은 `workbench/day4/outputs/`에, 코드는 `scripts/`에, 실험 기록 `experiments.md`는 `workbench/day4/` 바로 아래에 둡니다.

| 결과물 | 파일 | 점검 기준 |
|---|---|---|
| **한도안** | `scripts/limits_lp.py` · `limits_proposed.xlsx`(limits · constraints · summary) · `model_card.md` | 속성 테스트 8개 통과 · 걸린 제약 2개와 잠재가격을 쉬운 말 3줄로 · 규정과 다르게 정한 곳이 모델 카드에 있다 |
| **정책 실험** | `workbench/day4/experiments.md`(+ `outputs/exp/`) | 바꾼 것 · 예측 · 결과 · 한 줄 해석 — 기준 결과를 덮어쓰지 않았다 |
| **스트레스 표** | `stress_results.csv` · `loss_hist.png` · 내 시나리오 U1 해석 3줄 | 공식 기대손실 순서 · 시뮬레이션 평균 ±3% · '가정 시나리오에서의 추정' |
| **경보 워크플로** | `workbench/day4/rules/alert_rules.yml`(내 규칙 1개) · `scripts/ews.py` · `.github/workflows/d4-ews.yml` · `scripts/post_issue.py` | 속성 테스트 통과 · Actions 실행 링크(녹색 체크) · 자동 이슈 링크(다시 돌려도 1건) |
| **보고 파일** | 독자 카드 한 장 — Word 2쪽(`credit_report_2026-09.docx`) · 영업팀 표(`action_table.xlsx`) · 메일 5줄 중 하나 | 숫자 대조 불일치 0 · '권고(사람 승인 전)' 표기 · 초안 표시 |
| **검증 흔적** | `number_trace.csv` · `redteam.md`(반영 · 기각 이유) | 레드팀 지적을 사람이 가렸다 |
| PR | 내 저장소 PR 3개 — 실습 A `d4-limits` · 실습 B 워크플로 `d4-ews`(병합) · 실습 B 기록 | 제목 `4일차: …` · 본문 3줄(무엇을 · 결과 · 남은 질문) · 짝 코멘트 1개 |

- **제출 = push · PR**입니다. PR 링크를 **제출 칸**(제출 폼)에 붙여 넣으면 강사가 확인합니다. 제출 폼 링크는 당일 [사이트 홈](../index.md) 공지와 오픈채팅에 있습니다.
- **병합(merge)은 내가 GitHub 화면에서 직접** 누릅니다. 오늘은 워크플로 PR만 main에 병합합니다 — Actions의 `Run workflow` 버튼은 main에 있는 워크플로 파일에만 생기기 때문입니다.
- 점검 기준은 **'파일이 있다'가 아니라 검증한 흔적**입니다 — 테스트 통과 · 기대값과의 대조 · 숫자 대조 · 레드팀 판단 같은 것들입니다.
- PR 본문 · 커밋 메시지 · 보고서에 **회사 이름 · 실명 · 실제 숫자를 쓰지 않습니다.** 저장소가 공개입니다.
- 다 끝내지 못했어도 그대로 push하세요.

## 함께하는 규칙 {#rules}

- **1:1 순회**: 강사가 실습 동안 한 분씩 2–3분 확인합니다. 막히면 손을 들거나 빨간 표시를 올립니다.
- **짝과 서로 PR을 리뷰**: 서로의 PR에 코멘트 하나씩. 보는 것은 다섯 가지 — 바뀐 파일 · 커밋 메시지의 '왜' · 실데이터가 없는지 · 키가 없는지 · 한 줄 코멘트.
- **숫자보다 절차**: 난수 방식 · 솔버에 따라 P99나 바이어별 한도의 끝자리는 조금씩 다릅니다. 옆 사람과 숫자가 달라도 **목적함수 · 걸린 제약 · 평균이 공식 기대손실의 ±3% 안**이면 정상입니다. 이상하면 [어디서 갈렸나](../prompts/day4.md#mismatch)를 먼저 묻습니다.
- **한 번에 하나**: 프롬프트는 하나 보내고 결과를 읽은 뒤 다음으로 갑니다. 새 일은 새 대화에서 시작합니다.
- **허락 창은 읽고 승인**: 무엇을 · 어디에 · 지우는지 세 가지를 읽고 `1 Yes`. 파일 삭제 · 강제 push · `git reset --hard`는 거절합니다. **병합은 Claude Code에게 시키지 않고 내가 직접** 누릅니다. 권한(`permissions`)과 예약(`cron`) 줄은 반드시 내가 읽고 승인합니다.
- **예약 실행은 수업 뒤에 끕니다**: 워크플로에 예약 줄을 더했다면 연습이 끝난 뒤 Actions 화면에서 **Disable workflow**를 누릅니다(켜 두면 평일 아침마다 돌고 실패하면 메일이 옵니다).
- **현장 이야기를 들려 주세요**: 실습하다가 "우리 회사에서는 이렇게 한다"는 이야기가 나오면 말씀해 주세요 — 6일차 도입 기획의 재료가 됩니다.
