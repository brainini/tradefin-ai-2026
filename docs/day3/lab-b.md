## ② 엑셀에서 등급을 끌어 매기기 (15:15–15:35) {#b-excel}

오전 시연 4의 등급 시트를 **내 손으로** 만듭니다. 등급은 확률을 업무 언어로 바꾼 것입니다 — **C는 t 이상, B는 t/2 이상, A는 t/4 이상, 나머지는 S**입니다.

1. **임계값 t**를 정합니다. 실습 A-2에서 정한 값입니다. 비용비 5:1이면 이론값 **1 ÷ 6 ≈ 0.17**을 씁니다 — 시험 연체가 4건뿐이라 표의 최소 비용 t는 흔들리니, 이론값과 많이 다르면 **0.17이 안전합니다.** 내 비용비(3:1 · 10:1)로 정했다면 그 t를 쓰고, 등급 분포가 어떻게 달라지는지 봅니다.
2. `labs/day3/d3_grade_banding.xlsx`를 엽니다. **원본이 바뀌지 않게** 먼저 다른 이름으로 저장합니다(`workbench/day3/outputs/d3_grade_banding_mine.xlsx`). '보호된 보기'면 **편집 사용**을 누릅니다.
3. `기준` 시트의 **노란 칸 B3**(이름 `t`)에 내 t를 넣습니다. 아래 경계값 t/4 · t/2 · t가 저절로 계산됩니다.
4. `d3_scores.csv`를 엑셀로 열고(더블클릭) **머리글을 뺀 데이터 3열 150행**을 복사해 `pred` 시트 **A2**에 **값 붙여넣기** 합니다(머리글은 이미 있습니다).
5. `pred` 시트 **D2**에 IFS 수식을 씁니다. **가장 위험한 C부터** 검사합니다.

    ```text
    =IFS(C2>=t,"C",C2>=t/2,"B",C2>=t/4,"A",TRUE,"S")
    ```

    D2의 오른쪽 아래 작은 사각형(**채우기 핸들**)을 두 번 클릭하거나 150행까지 끌어 내립니다. `t`는 3단계의 이름(셀 `기준!B3`)이라 그대로 씁니다.
    - 순서를 바꿔 A를 먼저(`>=t/4`) 검사하면 B · C 행까지 A로 찍힙니다.
    - 모두 같은 등급이면 **이름 `t` 칸이 비었는지**, 모두 `#NAME?`이면 엑셀 2016 이하라서입니다 — 중첩 IF로 씁니다: `=IF(C2>=t,"C",IF(C2>=t/2,"B",IF(C2>=t/4,"A","S")))`
6. **조건부 서식**: D열을 선택 → 홈 › 조건부 서식 › 셀 강조 규칙 › 같음 → `C`는 빨강, `B`는 주황. 색에 더해 **글자(C · B)가 이미 있어** 색을 못 보는 사람도 읽을 수 있습니다.
7. **피벗 테이블**로 등급별 바이어 수를 셉니다(삽입 › 피벗 테이블 → 행에 `grade`, 값에 `buyer_id`의 개수). `기준` 시트의 분포 표(B12:C16)와 **같아야** 합니다.
8. 결과를 저장합니다. `pred` 시트를 연 채로 파일 › 다른 이름으로 저장 › **CSV UTF-8(쉼표로 분리)** → `workbench/day3/outputs/d3_grade_excel.csv`. (CSV는 보이는 시트 한 장만 저장합니다.)

**15:35 점검** — 등급 분포를 읽습니다. **S가 대부분**(125곳 넘게)이고 **C는 15–20곳 안팎**입니다(A2 프롬프트의 설정 그대로면 16–18곳, 강사 모델(3,807행)은 18곳). 확률이 '연체 없음'과 '연체 중'으로 갈라져서 **A · B에는 바이어가 거의 없는 것**이 정상입니다. 모델 설정 · 특성이 다르면 C가 10–25곳까지 달라질 수 있습니다. S가 100곳 아래이거나 C가 25곳을 넘으면 `t` 칸과 IFS 순서부터 봅니다.

## ③ 단조성 — 등급이 쓸모 있나 (15:35–15:42) {#b-mono}

등급이 **위험한 쪽일수록 실제 연체가 많은지**를 정답이 있는 시험셋으로 확인합니다. 예측 대상 150곳에는 정답이 없어서 이 점검을 할 수 없습니다.

1. 실습 A의 `d3_test_pred.csv`를 엑셀로 열어 **4열 88행**(`buyer_id` · `ref_date` · `late_30d` · `pd_30d`)을 `단조성` 시트 **A2**에 값 붙여넣기 합니다. 같은 `t`를 쓰는 등급(E열)은 수식이 미리 들어 있습니다.
2. 오른쪽 표(G:J)에서 등급별 **행 수 · 연체 수 · 실제 연체율**을 읽습니다. H7의 판정 문구도 봅니다.
3. **S 연체율 < C 연체율**인지 먼저 봅니다. A · B는 건수가 적어 순서가 뒤집혀 보일 수 있습니다.

!!! note "건수와 함께 읽습니다"
    시험셋 88행에 연체가 4건뿐이라 A · B 등급은 행이 0~몇 개이고, 연체율이 0%나 100%로 뜁니다. 오전 시연 4의 엑셀도 A가 작아서 ✗가 떴습니다. **건수가 충분한 등급끼리**(S와 C) 순서가 뒤집히면 등급 규칙을 업무에 쓸 수 없으니 `t`와 IFS 순서를 다시 봅니다.

**15:42 점검** — S 연체율이 C보다 낮습니다. 등급별 행 수와 연체 수를 `notes.md`에 적어 둘 한 줄을 정합니다.

2. **B-2 메모** — SHAP은 계산이 필요하니, 저장소의 **`labs/day3/shap_sample_3buyers.csv`**(B118 · B005 · B085의 점수 · 등급 · 위험을 올린 상위 3 · 낮춘 상위 2 — 강사 모델 값)를 대화에 붙이고 B4를 보냅니다. `[입력]`의 전역 상위 8 특성은 [프롬프트 페이지의 채팅 경로](../prompts/day3.md#chat-path)에 있는 줄을 그대로 씁니다. 메모의 결론 · 확인할 것 · 한계를 **내 말로 고치는 것**은 같습니다.
3. **B-2 환율** — ChatGPT에 `fx_forecast_inputs.csv`를 올려 B5와 같은 질문을 합니다(ChatGPT 무료는 하루 업로드가 3개 — 파일은 `d3_start_features.csv` · `d3_start_scoring.csv` · `fx_forecast_inputs.csv` 셋으로 정합니다).
4. **결과를 내려받아** 내 PC에서 같은 이름으로 `workbench/day3/outputs/`에 두고, **GitHub 웹에서 올립니다.**
    1. 내 저장소 화면의 브랜치 선택(`main ▾`)에서 `d3-model`이 있으면 고르고, 없으면 입력해 **Create branch**를 누릅니다.
    2. `workbench/day3/outputs/` 폴더에서 **Add file → Upload files**로 결과 파일을 끌어다 놓고, 커밋 메시지 첫 줄과 설명 칸(`왜:`)을 쓴 뒤 **Commit directly to the `d3-model` branch**를 고르고 **Commit changes**. `notes.md`는 `workbench/day3/`에서 같은 방법으로.
    3. 저장소 첫 화면의 **Compare & pull request** → 제목 · 본문 → **Create pull request**. 나머지(짝 리뷰 · 제출)는 ⑧과 같습니다.

## 막힐 때 {#troubleshooting}

| 증상 | 이렇게 해 보세요 |
|---|---|
| `model_v1.txt`가 없다 · 실습 A를 못 끝냈다 | [채팅 경로](#chat-path)가 '학습 + 점수'를 한 번에 합니다. 그래도 어려우면 손을 듭니다 — 점수 파일 없이 엑셀 단계를 연습할 수 있는 방법을 강사가 알려 드립니다 |
| `d3_scores.csv`가 150행이 아니다 · `pd_30d`가 0–100으로 보인다 | `d3_start_scoring.csv`를 읽었는지, 확률(0~1)이지 백분율이 아닌지 봅니다. 값은 0–1 그대로 두고 엑셀 서식만 %로 바꿉니다 |
| 엑셀에서 등급이 모두 같다 · 모두 `#NAME?` | 모두 같으면 **이름 `t` 칸이 비었는지**(`기준!B3`), `#NAME?`이면 엑셀 2016 이하라 IFS가 없는 것 — 중첩 IF로 씁니다 |
| 등급이 전부 S이거나 C가 너무 많다 | `t` 칸의 **값과 이름**을 봅니다(0.17인가 · 17인가). 비용비를 바꿨다면 분포가 달라지는 것이 정상입니다 |
| A가 너무 많다 | IFS를 **C부터** 검사했는지 봅니다 — 순서를 바꿔 A를 먼저 검사하면 B · C 행까지 A가 됩니다 |
| `d3_grade_excel.csv`에 한글이 깨진다 · 열이 한 칸에 모여 있다 | 저장 형식을 **CSV UTF-8(쉼표로 분리)**로 골랐는지, `pred` 시트가 활성이었는지 봅니다 |
| 엑셀과 AI의 등급이 한 행 다르다 | 그 행의 `pd_30d`가 경계값 바로 옆인지, 반올림 때문인지 봅니다. `>=` / `>` 차이도 확인합니다 |
| 단조성에서 S가 A나 B보다 높다 | A · B가 몇 행뿐이라 생기는 일입니다. 건수와 함께 읽고 **S와 C**를 비교합니다. S가 C보다 높으면 `t`와 IFS 순서를 다시 봅니다 |
| SHAP에서 `pred_contrib` 오류 · 열 개수가 다르다 | 학습 때와 **같은 열 순서 · 원-핫**으로 만든 입력을 줬는지 봅니다. B1의 "같은 특성 처리" 확인을 다시 시킵니다 |
| 워터폴의 한글이 □로 나온다 | `CLAUDE.md`의 글꼴 `tools/fonts/NanumGothic-Regular.ttf`를 쓰라고 다시 지시합니다 |
| 메모에 입력에 없는 숫자 · '때문에 연체'가 있다 | "입력에 없는 사실은 지우고 '입력에 없음'으로 바꿔라" · "'때문에 연체한다'를 '모델이 위험을 높게 본 근거'로 고쳐라"라고 시킵니다 |
| Prophet 설치 · 학습이 오래 걸린다 | ETS로 합니다. Prophet은 `uv sync --group forecast`가 먼저 필요하고 첫 학습이 느립니다 |
| 환율 그래프가 이상하다 · 6/5가 구간 안으로 나온다 | `date`가 날짜로 읽혔는지, **`split = train`(2026-05-29까지)만** 학습했는지, 95% 구간인지 봅니다 |
| `Compare & pull request`가 안 보인다 | 저장소 Pull requests 탭 → New pull request → base `main` ← compare `d3-model`. 브랜치를 push했는지 봅니다 |
| 비공개 저장소라 짝이 코멘트를 못 단다 | Settings → Collaborators로 짝을 초대(수락)합니다 — 또는 PR 본문에 짝의 `@아이디`를 적고 강사가 코멘트합니다 |
| 허락 창이 계속 뜬다 · push가 거부된다 | [실습 A의 막힐 때](lab-a.md#troubleshooting)와 같습니다 — 읽고 `1 Yes`, 로그인은 VS Code 계정 아이콘에서 |
