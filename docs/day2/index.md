## 파일 받기 {#files}

**내 저장소에서 명령 하나**면 됩니다. 08:30에 공개된 오늘 파일을 같은 경로로 내려받고, 작업 사본을 `workbench/day2/data/`에 만들어 줍니다.

- **15:35에 정답 20건(`d2_news_answer.csv`)이 열립니다.** 같은 명령을 한 번 더 실행하면 새로 올라온 파일만 받습니다.
- 막히면 아래 표에서 직접 받습니다. 저장소 없이 채팅 경로로 하는 사람은 이 방법을 씁니다.

1. 아래 표 맨 위 **`day2_files.zip`** 줄의 **받기**를 누릅니다(08:30 이후). 그 시각까지 공개된 오늘 파일이 전부 들어 있습니다.
2. 파일 탐색기(Mac: Finder)에서 **다운로드** 폴더를 엽니다.
3. 받은 zip 파일을 마우스 오른쪽 버튼으로 누르고 **모두 압축 풀기** → **압축 풀기**를 누릅니다. (Mac: zip 파일을 더블클릭)
4. 압축이 풀린 창에 보이는 **`D2`** 폴더를 바탕화면으로 끌어다 놓습니다.
5. 15:35에 열리는 정답 파일은 그 줄의 **받기**로 따로 받아 `D2` 폴더에 넣습니다.

## 데이터와 이용 조건 {#data}

- 오늘 쓰는 데이터는 모두 **(가상) 한빛정밀(주)의 합성 데이터**이거나 **공개 데이터**입니다. 한빛정밀(주)과 바이어 150곳, 뉴스 300건은 교육용 가상이며 실존 기업과 무관하고, 숫자는 실제 거래 기록이 아닙니다. 투자 · 여신 판단 자료가 아닙니다.
- 합성 데이터와 문서는 CC BY 4.0, 코드는 MIT입니다. 환율(`fx_krw_daily.csv` · 시트 `fx_at_ref`)은 미국 연준 H.10 환율(FRED 제공)로 'Public Domain: Citation Requested'이며 인용 방법은 저장소의 `data/external/ATTRIBUTION.md`에 있습니다. 오전 시연 4의 SEC 공시 값은 공개 공시이고 원문의 권리는 각 회사에 있습니다.
- 열 하나하나의 뜻은 [데이터 → 바이어 스냅샷 핵심 컬럼](../data.md#buyers)과 시작 파일의 `dictionary` 시트에, 라이선스 전문은 저장소의 `LICENSE-DATA.md` · `NOTICE.md`에 있습니다.
- **회사 실데이터 · 개인정보는 올리지 않습니다 — 익명화본도.** AI 서비스의 '모델 개선(학습)' 설정은 끄고 시작하고([사전 준비 — AI 학습 설정 끄기](../setup.md#ai-training)), 내 저장소는 공개이므로 **키 · 비밀번호 · 회사 자료는 커밋하지 않습니다.**
- 수집 점검은 **점검만** 합니다. 실제 뉴스 사이트에서 기사를 수집하거나 본문을 복사해 올리지 않습니다(남기는 것은 제목 · 날짜 · 주소 · 점수).

## 함께하는 규칙 {#rules}

- **1:1 순회**: 강사가 실습 동안 한 분씩 2–3분 확인합니다. 막히면 손을 들거나 빨간 표시를 올립니다.
- **짝과 서로 PR을 리뷰**: 서로의 PR에 코멘트 하나씩. 정답을 베끼는 것이 아니라 **AI가 놓친 곳을 서로 찾아 견주는** 용도입니다.
- **한 번에 하나**: 프롬프트는 하나 보내고 결과를 읽은 뒤 다음으로 갑니다. 새 일은 새 대화에서 시작합니다.
- **허락 창은 읽고 승인**: 무엇을 · 어디에 · 지우는지 세 가지를 읽고 `1 Yes`. 파일 삭제 · 강제 push · `git reset --hard`는 거절합니다. **머지는 Claude Code에게 시키지 않고 내가 직접** 누릅니다.
- **현장 이야기를 들려 주세요**: 실습하다가 "우리 회사에서는 이렇게 한다"는 이야기가 나오면 말씀해 주세요 — 6일차 도입 기획의 재료가 됩니다.

!!! success "오늘의 습관 네 가지"
    1. **규칙을 먼저 문서로** — 무엇을 어떻게 고칠지는 사람이 정하고, 스크립트와 테스트는 그 규칙을 따릅니다.
    2. **변환했으면 검증한다** — 행 수 · 합계 · 손계산 한 건 · 정답과의 비교. AI가 쓴 쿼리와 점수도 숫자로 확인합니다.
    3. **기준일 이전 정보만** — 환율은 기준일 또는 직전 영업일, 뉴스는 기준일 전 30일. 성능이 너무 좋으면 먼저 의심합니다.
    4. **일 하나 = 브랜치 하나 = PR 하나** — 커밋 메시지에 무엇과 왜를 남기고, 비밀값 · 실데이터는 올리지 않습니다.

## 정리 · 자가 점검 · 내일 예고 {#tomorrow}

**오늘 배운 것 다섯 줄**

1. 브랜치 · PR · 리뷰 · worktree로 AI 작업을 나누고 안전하게 합친다.
2. 전처리 = 진단 → 규칙 → 스크립트 → 검증 → 기록.
3. 특성은 기준일 이전 정보만 — 특성 사전에 시점 점검 칸을 둔다.
4. SQL · DuckDB로 표를 잇고, AI가 쓴 쿼리는 숫자로 검증한다.
5. 텍스트 → 구조화 출력 → 골든셋 평가 → 프롬프트 버전 관리.

**자가 점검** — 체크 표시를 눌러 보세요.

- [ ] 나는 이슈 → 브랜치 → 커밋 → PR → 리뷰 → 머지의 흐름을 직접 밟고, worktree로 두 작업을 나란히 할 수 있다
- [ ] 나는 데이터를 규칙 문서 · 스크립트 · 테스트로 정제하고, 결측의 이유에 따라 채우는 법을 고를 수 있다
- [ ] 나는 특성이 기준일 이전 정보만으로 만들어졌는지 점검하고 특성 사전에 남길 수 있다
- [ ] 나는 AI가 쓴 SQL을 행 수 · 합계 · 손계산 · 빈값으로 검증할 수 있다
- [ ] 나는 가져와도 되는 데이터인지 점검하고(API · robots.txt · 약관), 뉴스를 구조화 출력으로 점수화해 골든셋으로 검증할 수 있다
