## B-1 · 바이어 데이터 진단과 사전 {#b1}

### ① 진단 (15:00–15:20) {#b1-diagnose}

1. Claude Code **새 대화**를 열고 모드가 **Manual**인지 봅니다.
2. 프롬프트 **B1**을 붙여 넣습니다. 첫 줄이 **"원본은 수정하지 마"**, 마지막 줄이 **"진단만 하고, 고치는 코드는 아직 만들지 마"**입니다.

    ??? example "프롬프트 B1 — 펼쳐서 복사"
        ```text
        @data/day1/d1_buyers_raw.xlsx 는 바이어 150곳 목록이다. 원본은 수정하지 마.
        1) 열마다 유형 · 결측 수 · 이상한 표기 예 3개 · 문제 · 처리 제안
        2) 중복 행, 숫자처럼 보이는 글자, 날짜 형식 종류는 따로 표로
        결과는 outputs 폴더의 d1_quality_report.md
        진단만 하고, 고치는 코드는 아직 만들지 마.
        ```

3. 허락 창이 여러 번 뜹니다. 읽기만 하는 명령인지 확인하고 `1 Yes`를 누릅니다.

5. **AI가 놓친 문제를 1개 이상 직접 찾습니다.** `workbench/day1/data/`에 복사한 사본을 엑셀로 열고(**저장하지 않습니다**), 열마다 필터 단추(▼)로 값 목록을 훑어 봅니다. 열마다 이렇게 물어보세요 — 유형이 맞나? 같은 값이 다르게 적히지 않았나? 비어 있는 칸이 있나? 범위를 벗어난 값이 있나? 같은 행이 두 번 나오나?

7. 원본이 그대로인지 터미널에서 `git status`로 확인합니다 — `data/` 아래가 바뀌었다고 나오면 안 됩니다.

### ② 결제조건 코드표 (15:20–15:35) {#b1-codes}

장부에는 같은 결제방식이 `T/T 30 days after B/L`, `OA60`, `L/C at sight` …처럼 **자유롭게** 적혀 있습니다. 오전의 결제방식 설명을 근거로 **표준 코드 7개**로 묶는 매핑표를 만듭니다.

??? example "프롬프트 B2 — 펼쳐서 복사"
    ```text
    @data/day1/d1_buyers_raw.xlsx 의 payment_terms_raw 열에 나오는 표기를 모두 모아,
    표준 코드 7개(TT_ADV 선수금 · TT_SPLIT_30_70 선수+잔금 · LC_SIGHT · LC_USANCE · DP · DA · OA)로 나누는 매핑표를 만들어 줘.
    열: 원래 표기 | 표준 코드 | 판단 근거(어느 단어로) | 확신(높음/낮음)
    판단이 애매하면 '검토 필요'로 두고 추측하지 마.
    결과는 outputs 폴더의 d1_code_table.csv 로, 엑셀에서도 한글이 깨지지 않게 utf-8-sig로 저장해.
    ```

1. B2를 붙여 넣고 허락 창을 읽어 승인합니다. 결과는 `workbench/day1/outputs/d1_code_table.csv`입니다.
2. CSV를 VS Code에서 열어 **'확신: 낮음'** 행과 **'검토 필요'**로 남은 행을 찾습니다.
3. 그 행들을 **내가 판단해** `표준 코드` 칸을 고칩니다. 판단 기준은 오전에 본 결제방식입니다.

    | 표준 코드 | 뜻 | 표기에서 찾을 단서 |
    |---|---|---|
    | `TT_ADV` | 전신송금 **선수금**(선적 전 전액) | in advance · 선수금 · 선입금 |
    | `TT_SPLIT_30_70` | **선수금 + 잔금** 분할 | 선수금 비율과 잔금 시점이 **함께** 적힘 |
    | `LC_SIGHT` | L/C **일람불** | L/C · at sight · 일람불 |
    | `LC_USANCE` | L/C **기한부** | L/C · usance · 기한부(N일) |
    | `DP` | D/P 지급인도 추심 | D/P |
    | `DA` | D/A 인수인도 추심 | D/A |
    | `OA` | **사후송금**(외상) | O/A · open account · T/T라도 **선적 후 N일** 뒤 송금 |

    "T/T"라고만 적혀 있으면 안전한지 위험한지 알 수 없습니다 — **시점**(선적 전인가, 선적 후 N일인가)이 정합니다.
4. 점검 기준은 **'검토 필요' 0행**입니다. 판단이 정말 어려운 표기는 `판단 근거` 칸에 이유를 적고 가장 가까운 코드를 고릅니다.

!!! info "CSV를 엑셀로 열 때"
    이 CSV는 한글이 깨지지 않게 UTF-8(BOM 포함)로 저장했습니다. 그래도 깨져 보이면 A-1 ①처럼 엑셀 **데이터 › 텍스트/CSV에서**로 열고 **파일 원본을 65001: UTF-8**로 고릅니다.

4. 커밋하고 push합니다.

### ⑤ 손 검산 (16:15–16:25) {#b2-check}

AI가 코드로 낸 숫자 하나를 **코드 없이 마우스로** 다시 만들어 맞춰 봅니다. 차트 3의 **결제방식 하나**(예: 연체 바이어 비율이 눈에 띄는 것)를 고릅니다.

#### 엑셀에 열 두 개 더하기 {#new-columns}

1. 탐색기에서 `data/day1/d1_buyers_raw.xlsx`를 `workbench/day1/data/`로 **복사**하고, 그 사본을 엑셀로 엽니다(원본은 건드리지 않습니다).
2. B2의 `d1_code_table.csv`를 같은 통합 문서의 새 시트 `코드표`로 불러옵니다(**데이터 › 텍스트/CSV에서**, 파일 원본 UTF-8). A열이 원래 표기, B열이 표준 코드입니다.
3. `buyers` 시트 오른쪽 끝에 열 두 개를 더합니다(`payment_terms_raw`는 I열, `max_dpd_days`는 L열입니다).

    | 새 열 | 수식(2행) | 뜻 |
    |---|---|---|
    | `표준코드` | `=XLOOKUP(TRIM(I2), 코드표!A:A, 코드표!B:B, "미분류")` | 코드표로 결제방식을 찾는다 |
    | `연체` | `=IFERROR(IF(--L2>0,1,0), "")` | 연체일이 0보다 크면 1, 숫자가 아닌 칸은 빈칸 |

    수식을 아래 끝까지 채웁니다(셀 오른쪽 아래 모서리 더블클릭).

#### XLOOKUP이 없을 때 {#xlookup-alt}

엑셀 2019 이하에서는 `#NAME?`이 나옵니다. 같은 일을 하는 수식입니다.

```text
=IFERROR(INDEX(코드표!B:B, MATCH(TRIM(I2), 코드표!A:A, 0)), "미분류")
=IFERROR(VLOOKUP(TRIM(I2), 코드표!A:B, 2, FALSE), "미분류")
```

#### 피벗으로 숫자 하나 만들기

1. 데이터 범위를 선택하고 **삽입 › 피벗 테이블**을 만듭니다.
2. **행**에 `표준코드`, **값**에 `buyer_id`(개수)와 `연체`(합계)를 넣습니다. 연체 바이어 **비율 = 연체 합계 ÷ 바이어 수**입니다(옆 칸에 나눗셈).
3. 같은 피벗에서 **피벗 차트**(막대)를 하나 그립니다 — 끌어다 놓기만으로 그리는 차트입니다. 노트북의 차트 3과 **모양**을 견줍니다.
4. 노트북이 보여 준 같은 결제방식의 값과 **숫자**를 맞춰 봅니다.

#### 맞춰 본 결과 적기

`workbench/day1/outputs/d1_eda_notes.md`에 **'손 검산'** 절을 더해 적습니다.

```text
## 손 검산
- 대상: (결제방식 코드) 연체 바이어 비율
- 노트북: (값)   피벗: (값)   → 일치 / 불일치
- 불일치라면 원인: (어디서 갈렸나)
```

!!! success "숫자가 다르면 그것이 정답입니다"
    AI 숫자와 피벗 숫자가 **다르면 원인을 적는 것이 오늘의 과제**입니다. 코드표를 반영했는지 · 같은 행이 두 번 세어졌는지 · 숫자 칸의 글자나 빈칸을 어떻게 처리했는지 · '검토 필요' 행을 어떻게 했는지 중 **어디서 갈렸는지** 찾아 적습니다. 같게 나오면 "맞았다"고 적고, 노트북이 어떤 처리를 했는지 한 줄 덧붙입니다.

!!! tip "피벗이 어렵다면"
    표준코드 열과 연체 열을 만든 뒤 `=COUNTIF(X:X,"OA")`(바이어 수)와 `=SUMIFS(Y:Y, X:X, "OA")`(연체 수)로 한 결제방식만 세어도 같은 숫자 하나가 나옵니다(X는 `표준코드`, Y는 `연체` 열입니다).

### ⑥ 현안 정의 (16:25–16:35) {#b2-issue}

분석의 첫 칸은 **"무엇을 결정하려는 분석인가"**입니다. 오늘의 숫자로 **결제방식별 금융 현안**을 한 쪽으로 정의합니다.

??? example "프롬프트 B5 — 펼쳐서 복사"
    ```text
    @workbench/day1/outputs/d1_eda_notes.md 와 @workbench/day1/outputs/d1_code_table.csv 를 근거로,

    - 숫자는 파일에 있는 것만 그대로. 새 숫자·비율을 만들지 마.
    - 결제방식의 일반 구조를 설명하는 문장 끝에는 '(일반 설명)'.
    - 규정·통계는 쓰지 말고 '확인 필요'로 남겨.
    - 바이어 5곳 미만 그룹은 '표본 작음 — 결론 보류'.
    - '내 업무라면' 칸은 비워 둬 — 내가 쓴다(공개 저장소라 회사 이름·실명·실제 숫자 없이).

    ```

1. B5를 붙여 넣어 `workbench/day1/outputs/d1_issue_definition.md` 초안을 받습니다.

3. **⑤ '내 업무라면'을 내가 직접** 씁니다 — 내 업무에서 이 현안에 해당하는 결제방식 · 바이어의 **상황만** 적습니다.

!!! danger "공개 저장소입니다"
    '내 업무라면' 칸과 메모에는 **회사 이름 · 실명 · 실제 숫자를 쓰지 않습니다.** 회사 실데이터는 익명화본이라도 올리지 않습니다. 실수로 올렸다면 파일을 지우는 것으로 끝나지 않습니다(커밋 이력에 남습니다) — 바로 강사에게 알립니다.
