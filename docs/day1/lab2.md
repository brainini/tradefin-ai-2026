## 목표 {#goal}

1. AI에게 데이터를 **고치지 말고 진단만** 시켜, 무엇이 이상한지 목록부터 받는다.
2. AI에게 요약표·차트를 받되 **결제조건 매핑표와 사용한 코드**까지 받는다.
3. 엑셀로 결제방식을 코드 7종으로 정리하고, 연체 구간을 만들고, **피벗 3개**로 같은 숫자를 다시 만든다.
4. AI 숫자와 엑셀 숫자가 다르면 **왜 다른지** 찾아 적는다. 이것이 이 실습의 핵심입니다.
5. 숫자가 붙은 **인사이트 3개**를 쓴다.

??? note "결제방식 코드 7종 — '미분류'를 정리할 때 참고"
    | 코드 | 뜻 | 대금 받는 시점 | 위험을 지는 쪽 |
    |---|---|---|---|
    | `TT_ADV` | 선수금 송금(T/T in advance) | 선적 전 | 수출자 위험은 거의 없음 |
    | `TT_SPLIT_30_70` | 분할 송금: 30% 선수금 + 70% 선적 후 송금 | 30% 선적 전, 70% 선적 후 | 잔금 70%는 수출자 |
    | `OA` | 사후송금(Open Account) — 선적 후 정해진 날수 뒤 송금 | 선적 후 30·60·90일 | 수출자 전부 |
    | `DA` | 인수인도조건 추심(D/A, Documents against Acceptance) | 어음 인수 후 만기 | 수출자(추심은행은 지급을 보증하지 않음) |
    | `DP` | 지급인도조건 추심(D/P, Documents against Payment) | 대금을 내야 서류를 내줌 | 수출자(안 내면 물품 반송·재판매) |
    | `LC_SIGHT` | 일람불 신용장(Sight L/C) | 서류 제시·심사 후 | 개설은행·국가(서류 하자는 수출자) |
    | `LC_USANCE` | 기한부 신용장(Usance L/C) | 만기 | 개설은행·국가 |
    | `확인필요` | 판단이 어려운 표기(임시) | — | 사람이 확인한 뒤 코드로 바꾼다 |

    `00_코드표` 시트 오른쪽에도 같은 표가 있습니다. 자세한 설명: [데이터 → 결제방식 코드](../data.md#codes)

!!! tip "AI 표를 템플릿에 붙일 때"
    붙일 칸을 **마우스 오른쪽 버튼**으로 누르고 **붙여넣기 옵션 → 대상 서식에 맞추기**를 고르면 템플릿의 색과 글꼴이 유지됩니다. 그냥 ++ctrl+v++ 해도 내용은 같습니다.

## 실습 {#steps}

=== "🟢 Basic"

    **준비 (14:00–14:05)**

    1. 짝과 드라이버·내비게이터를 정합니다.
    2. 강사 화면의 피벗 시범을 함께 봅니다(5분).
    3. [파일 받기](#files)에서 `d1_buyers_raw.xlsx`와 `data_dictionary.xlsx`를 `D1` 폴더에 받습니다. 템플릿은 Lab1에서 쓰던 파일을 그대로 씁니다.

    **1단계 — 진단만, 수정 금지 (P1-3) → `03_EDA` ①**

    4. AI 화면에서 **새 채팅**을 엽니다.
    5. 입력창의 **＋**(또는 클립) → **파일 업로드** → `d1_buyers_raw.xlsx`를 올립니다. 엑셀 파일이 안 올라가면 `d1_buyers_raw.csv`를 올립니다.
    6. **P1-3**을 붙여 넣고 `[이번 입력]`을 파일 `d1_buyers_raw.xlsx(시트 buyers)` · 데이터 사전 `없음`으로 바꿔 보냅니다.

    7. 답에 **구조 요약 · 열 프로파일 · 오염 목록 · 한 줄 경고 · 코드**가 있는지 봅니다. AI가 '정리한 표'나 새 파일을 내놓으면 받지 않고 `고친 결과는 버리고, 원본 그대로 센 숫자로 다시 진단만 하라.`를 보냅니다.
    8. **오염 목록** 표의 첫 데이터 줄부터 마지막 줄까지(머리글 줄은 빼고) 마우스로 끌어 선택하고 ++ctrl+c++ 합니다.
        - 템플릿의 붙일 자리는 7–21행(15줄)입니다. 오염 목록이 **14줄보다 길면** 먼저 같은 채팅에 `오염 목록 표를 14줄 이내로 다시 써라. 같은 유형은 한 줄로 합쳐라.`를 보낸 뒤 복사합니다(남는 한 줄은 43번에서 씁니다).
    9. 템플릿 `03_EDA` 시트의 **A7** 칸을 클릭하고 ++ctrl+v++ 합니다. 유형 · 열 · 해당 행 수 · 예시 · 오늘 분석에 주는 영향 · 내일 고칠 방법이 템플릿 머리글(6행)과 같은 순서로 들어갑니다. 머리글 줄까지 붙었으면 그 줄만 지웁니다.
    10. 목록에서 **2개**를 골라 원본에서 직접 확인합니다: `d1_buyers_raw.xlsx`를 열고(위쪽에 노란 띠가 뜨면 **편집 사용**), 해당 열 머리의 ▼를 누르면 그 열에 들어 있는 값 목록이 보입니다.
    11. AI가 말한 예시 값이 실제로 있으면 그 행 **G열 ▼에서 ✔**, 없으면 **✘**를 고릅니다.
    12. 구조 요약의 **행 수**와 **고유 buyer_id 수**를 `03_EDA`의 **A23** 칸(진단 목록 아래 빈칸)에 적어 둡니다. 둘이 다르면 그 자체가 발견입니다.

    14. **P1-4**를 붙여 넣고 `[이번 입력]`을 파일 `d1_buyers_raw.xlsx(시트 buyers)` · 코드표 `data_dictionary.xlsx의 payment_terms_map 시트`(13번을 건너뛰었으면 `없음`)로 바꿔 보냅니다.

    15. **표0 매핑표**부터 봅니다 — `payment_terms_raw`의 제각각인 표기를 코드 7종(TT_ADV · TT_SPLIT_30_70 · OA · DA · DP · LC_SIGHT · LC_USANCE)으로 어떻게 묶었는지와 출처(코드표 / AI 규칙 / 사람 판단 필요)가 보입니다. 맨 아래 행 수 합계가 P1-3 구조 요약의 행 수와 같은지 확인합니다.
    16. 출처가 'AI 규칙'이나 '사람 판단 필요'인 표기는 엑셀에서 **'미분류'가 될 후보**입니다. 3단계에서 다시 봅니다.
    17. 매핑표·표1~3·코드 중 빠진 것이 있으면 `표0 매핑표부터 다시 보여라.` 또는 `사용한 코드 전체를 보여라.`를 보냅니다.
    18. **표1**(결제방식별)을 끌어 선택해 복사하고 `03_EDA`의 **A26** 칸에 붙입니다. 이어서 **표3**(국가별 상위 10)을 표1 아래 한 줄 띄워 붙입니다. 붙일 자리는 점선 안 59행까지입니다.
        - 표0 매핑표처럼 긴 표와 표2·해석·주의·코드는 03_EDA에 다 들어가지 않습니다. 남겨 두고 싶으면 시트 탭 줄 오른쪽 **＋**(새 시트)를 눌러 새 시트 A1에 붙입니다(선택).
        - '병합된 셀의 일부를 변경할 수 없습니다'가 뜨면 붙일 표가 59행을 넘은 것입니다 → 그 표는 새 시트에 붙입니다.
        - 차트는 마우스 오른쪽 → **이미지 복사** → 점선 오른쪽 빈 곳에 붙입니다.
    19. **B60** 칸에 AI가 쓴 정의(연체 기준 · 숫자가 아닌 칸 처리 · 결제조건 매핑 방법)를 한 줄로 적고, **B61 ▼**에서 코드를 받았는지 `예`/`아니오`를 고릅니다.
    20. AI 숫자 3개를 `03_EDA` 대조표 **B열**에 적습니다 — B65 전체 연체 바이어 비율(표1 합계 행) · B66 O/A 연체 바이어 비율(표1 OA 행) · B67 91일 이상(91+) 바이어 수(표1 합계 행). 비율은 % 기호까지 적습니다(예: `12.5%`).

    **3단계 (앞) — 바이어 시트를 템플릿으로 복사하고 표 만들기**

    21. `d1_buyers_raw.xlsx`와 템플릿을 **둘 다** 엽니다. 노란 띠(제한된 보기)가 뜬 파일은 **편집 사용**을 눌러야 22번의 이동/복사가 됩니다.
    22. `d1_buyers_raw.xlsx` 아래쪽의 **buyers** 시트 탭을 마우스 오른쪽 버튼으로 누르고 **이동/복사**를 고릅니다.
    23. '대상 통합 문서'에서 **d1_end_eda_template.xlsx**(또는 내가 저장한 이름)를 고르고, '다음 시트의 앞에'에서 **(끝으로 이동)**을 고릅니다.
    24. 아래 **복사본 만들기**를 체크하고 **확인**을 누릅니다. 이제 템플릿에 `buyers` 시트가 생겼습니다.
    25. 템플릿의 `buyers` 시트에서 A2 셀을 클릭합니다.

    27. 위쪽 **테이블 디자인** 탭 → 맨 왼쪽 **표 이름** 칸을 클릭하고 `tbl_buyers`로 바꾼 뒤 ++enter++ 를 누릅니다.

    **3단계 (앞) — 새 열 4개 만들기**
    { #new-columns }

    표 오른쪽 끝 바로 옆(X열)에 열 이름을 쓰면 표가 저절로 넓어지고, 2행에 수식을 한 번 넣으면 아래 행 전체에 자동으로 채워집니다. 아래 순서대로 만듭니다(`dpd_num`이 있어야 뒤의 두 열이 계산됩니다).

    28. **X1** 셀을 클릭하고 `payment_method`를 입력한 뒤 ++enter++ 를 누릅니다.
    29. **X2** 셀에 아래 수식을 붙여 넣고 ++enter++ 를 누릅니다. 결제조건 원문을 `00_코드표`(표 이름 `tbl_codes`)에서 찾아 코드로 바꾸고, 표에 없으면 **"미분류"**라고 씁니다.

        ```text
        =XLOOKUP(UPPER(TRIM([@payment_terms_raw])),tbl_codes[raw_upper],tbl_codes[payment_method],"미분류")
        ```

        **#NAME?**이 나오면 XLOOKUP이 없는 엑셀입니다 → 바로 아래 [대안 수식](#xlookup-alt)을 씁니다.

    30. **Y1**에 `dpd_num`을 입력하고, **Y2**에 아래 수식을 넣습니다. 연체일이 숫자가 아닌 칸(글자가 섞인 칸)은 빈칸으로 둡니다.

        ```text
        =IFERROR(--[@max_dpd_days],"")
        ```

    31. **Z1**에 `aging_bucket`을 입력하고, **Z2**에 아래 수식을 넣습니다. 연체일을 구간(Current · 1-30 · 31-60 · 61-90 · 91+)으로 나누고, 빈칸은 "확인필요"로 둡니다.

        ```text
        =IF([@dpd_num]="","확인필요",IF([@dpd_num]<=0,"Current",IF([@dpd_num]<=30,"1-30",IF([@dpd_num]<=60,"31-60",IF([@dpd_num]<=90,"61-90","91+")))))
        ```

    32. **AA1**에 `is_overdue`를 입력하고, **AA2**에 아래 수식을 넣습니다. 연체면 1, 아니면 0, 연체일을 모르면 빈칸입니다.

        ```text
        =IF([@dpd_num]="","",--([@dpd_num]>0))
        ```

    33. 네 열이 맨 아래 행(154행)까지 채워졌는지 ++ctrl+down++ 으로 내려가 확인합니다.

    !!! tip "XLOOKUP이 없을 때 — 같은 일을 하는 대안 수식"
        Excel 2019·2016 이하에서는 29번 수식 대신 아래 둘 중 하나를 X2에 넣습니다. 결과는 같습니다(템플릿 `00_코드표` 오른쪽에도 같은 수식이 있습니다).
        { #xlookup-alt }

        **INDEX + MATCH** (권장)

        ```text
        =IFERROR(INDEX(tbl_codes[payment_method],MATCH(UPPER(TRIM([@payment_terms_raw])),tbl_codes[raw_upper],0)),"미분류")
        ```

        **VLOOKUP**

        ```text
        =IFERROR(VLOOKUP(UPPER(TRIM([@payment_terms_raw])),tbl_codes[[raw_upper]:[payment_method]],2,FALSE),"미분류")
        ```

        VLOOKUP의 숫자 `2`는 '`raw_upper`부터 세어 두 번째 열(`payment_method`)'이라는 뜻입니다.

    **(14:50–15:00 휴식 — 15:00에 드라이버·내비게이터 교대)**

    **3단계 (뒤) — '미분류' 정리하기**

    34. `payment_method` 머리글의 ▼를 누르고 **모두 선택**을 해제한 뒤 **미분류**만 체크 → **확인**을 누릅니다.
    35. 남은 행의 `payment_terms_raw` 원문을 읽고, 위의 [결제방식 코드 7종](#files) 중 어느 것인지 정합니다. 2단계의 AI 매핑표도 참고하되, 애매하면 짝과 상의합니다 — 여러분이 무역금융 전문가입니다.
    36. 그 행의 `payment_terms_raw` 칸을 클릭하고 ++ctrl+c++ 를 누릅니다.
    37. `00_코드표` 시트로 가서 `tbl_codes` 표 바로 아래 **첫 빈 줄의 A칸**(raw_variant — 처음에는 48행, 다음에는 49행 …)을 마우스 오른쪽 버튼으로 누르고 **붙여넣기 옵션 → 값**(123 아이콘)을 고릅니다. 표가 한 줄 늘어납니다.
    38. 같은 줄 **B칸**(raw_upper)에 `=UPPER(TRIM([@raw_variant]))`를 입력합니다(대문자로 직접 써도 됩니다).
    39. **C칸**(payment_method)의 ▼에서 코드를 고릅니다. 판단이 어려우면 임시로 **확인필요**를 고릅니다.
    40. **D칸**(설명)에 그렇게 판단한 이유를 한 줄 씁니다.
    41. `buyers` 시트로 돌아와 그 행의 `payment_method`가 '미분류'에서 코드(예: `OA`)로 바뀌었는지 봅니다. 필터를 건 상태라 행은 그대로 보입니다 — **데이터** 탭 → **다시 적용**을 누르면 남은 '미분류'만 다시 보입니다. 코드로 안 바뀌었으면 원문을 정확히 옮겼는지(오탈자) 확인합니다.
    42. '미분류' 행이 모두 사라질 때까지 35–41번을 반복합니다. 같은 표기는 한 번만 추가하면 그 표기를 쓴 행이 모두 바뀝니다(대소문자·앞뒤 공백만 다른 표기도 같은 표기로 칩니다).
    43. 판단이 애매해 '확인필요'로 둔 표기는 `03_EDA` 진단 목록 표의 빈 줄에 유형 '결제조건 애매'로 한 줄 추가하고 **왜 애매한지** 적습니다. 애매한 결제조건 자체가 위험 신호일 수 있습니다.
    44. `payment_method` 머리글의 ▼ → **"payment_method"에서 필터 해제**를 눌러 전체 행을 다시 봅니다.

    **3단계 (뒤) — 피벗① 결제방식 × 연체 구간 (행 비율)**

    45. `tbl_buyers` 안 아무 셀을 클릭하고 **삽입** 탭 → **피벗 테이블**을 누릅니다(메뉴가 펼쳐지면 **표/범위에서** — 버전에 따라 '테이블/범위에서').
    46. '표/범위'가 `tbl_buyers`인지 보고, **기존 워크시트**를 고릅니다.
    47. '위치' 칸을 클릭한 뒤 `04_피벗` 시트 탭 → **A22** 셀을 클릭하고 **확인**을 누릅니다.
    48. 오른쪽 '피벗 테이블 필드' 창에서 `payment_method`를 **행**, `aging_bucket`을 **열**, `buyer_id`를 **값**으로 끌어 놓습니다. 값에 '개수: buyer_id'가 보입니다. 행에 '확인필요'(내가 판단을 미룬 결제조건)나 열에 '확인필요'(연체일이 숫자가 아닌 행)가 보여도 정상입니다.
    49. 이 상태(개수)에서 **91+ 열 맨 아래 총합계**를 `03_EDA` **C67**(91+ 바이어 수의 엑셀 숫자)에 적습니다.
    50. 값 영역의 '개수: buyer_id' ▼ → **값 필드 설정** → **값 표시 형식** 탭 → **행 합계 비율**을 고르고 **확인**을 누릅니다.
    51. 열 순서를 Current → 1-30 → 31-60 → 61-90 → 91+ 로 맞춥니다: 'Current' 머리글 칸을 마우스 오른쪽 버튼 → **이동** → **'Current'을(를) 처음으로 이동**. (칸 테두리를 잡고 끌어 옮겨도 됩니다.)

    **3단계 (뒤) — 100% 누적 막대 차트**

    52. 피벗① 안 아무 셀을 클릭하고 **피벗 테이블 분석** 탭 → **피벗 차트**를 누릅니다.
    53. **가로 막대형** → **100% 기준 누적 가로 막대형**을 고르고 **확인**을 누릅니다.
    54. 차트 제목을 클릭해 `결제방식별 연체 구간 구성(행 비율)`으로 바꾸고(제목이 없으면 차트 오른쪽 위 **＋** → **차트 제목** 체크), 차트를 **J22** 근처 점선 칸으로 끌어 놓습니다.

    **3단계 (뒤) — 피벗② 국가별 연체 바이어 비율 상위 10**

    55. `tbl_buyers` 안 아무 셀 → **삽입** → **피벗 테이블** → **기존 워크시트** → 위치 `04_피벗` 시트 **A42** → **확인**.
    56. `country_code`를 **행**으로, `is_overdue` · `dpd_num` · `buyer_id`를 **값**으로 끌어 놓습니다.
        - 상위 10 필터 전에는 나라가 모두 보여 피벗이 61행 안내 글까지 길어집니다. '…이미 데이터가 있습니다. 바꾸시겠습니까?' 창이 뜨면 **확인**을 누릅니다. 안내 글만 덮이고, 60번에서 상위 10 필터를 걸면 다시 짧아집니다.
    57. 'is_overdue' 값 ▼ → **값 필드 설정** → **값 요약 기준**에서 **평균** → 아래 **표시 형식** → **백분율** → **확인** → **확인**(창이 두 개). 이 숫자가 그 나라의 **연체 바이어 비율**입니다.
    58. 'dpd_num' 값 ▼ → **값 필드 설정** → **평균** → **확인**(평균 연체일). 'buyer_id'는 개수 그대로 둡니다(바이어 수 = 표본 크기).
    59. 맨 아래 **총합계** 줄의 '평균: is_overdue'를 `03_EDA` **C65**(전체 연체 바이어 비율의 엑셀 숫자)에 적습니다. 상위 10 필터를 걸기 **전에** 적어야 전체 값입니다.
    60. 행 레이블(`country_code`) ▼ → **값 필터** → **상위 10** → '상위 10 항목, 기준: 평균: is_overdue'로 맞추고 **확인**.
    61. 다시 행 레이블 ▼ → **기타 정렬 옵션** → **내림차순 기준**에서 '평균: is_overdue'를 고르고 **확인**.
    62. 바이어 수가 **5곳 미만**인 나라는 옆 칸에 '표본 작음'이라고 적습니다. 바이어 2곳 중 1곳이 연체면 50%가 됩니다.

    **3단계 (뒤) — 피벗③ 권역 × 보험 가입**

    63. `tbl_buyers` 안 아무 셀 → **삽입** → **피벗 테이블** → **기존 워크시트** → 위치 `04_피벗` 시트 **A62** → **확인**.
    64. `region`을 **행**, `ksure_insured`(K-SURE 부보 여부 Y/N)를 **열**, `buyer_id`를 **값**(개수)으로 끌어 놓습니다.
    65. 세 피벗과 차트가 모두 `04_피벗` 시트에 있는지 확인합니다. '피벗 테이블 보고서는 겹칠 수 없습니다'가 뜨면 **피벗 테이블 분석** → **피벗 테이블 이동**으로 더 아래 빈칸에 둡니다.

    !!! tip "15:25에 피벗①을 못 끝냈다면 — 지름길"
        피벗②·③과 차트는 건너뛰고, 새 열 4개만 있으면 되는 아래 수식을 `03_EDA`의 각 칸에 하나씩 붙여 넣은 뒤 4단계로 갑니다. C65·C66은 칸이 미리 % 형식이라 그대로 백분율로 보입니다.

        **C65** 전체 연체 바이어 비율 — '확인필요' 행(빈칸)은 빼고 계산하므로 피벗② 총합계와 같은 정의입니다.

        ```text
        =AVERAGE(tbl_buyers[is_overdue])
        ```

        **C66** O/A 연체 바이어 비율(66번 수식과 같습니다)

        ```text
        =AVERAGEIFS(tbl_buyers[is_overdue],tbl_buyers[payment_method],"OA")
        ```

        **C67** 91일 이상(91+) 바이어 수

        ```text
        =COUNTIF(tbl_buyers[aging_bucket],"91+")
        ```

    **4단계 — AI 숫자 vs 엑셀 숫자 대조 → 차이 원인 (`03_EDA` ③)**

    66. `03_EDA` **C66** 칸(O/A 연체 바이어 비율의 엑셀 숫자)에 아래 수식을 넣습니다. 피벗②와 같은 계산(`is_overdue` 평균)을 O/A 행만 골라서 합니다.

        ```text
        =AVERAGEIFS(tbl_buyers[is_overdue],tbl_buyers[payment_method],"OA")
        ```

    67. C66이 `12.3%`처럼 백분율로 보이는지 봅니다(칸이 미리 소수 첫째 자리 % 형식입니다). 소수(예: `0.123`)로 보일 때만 **홈** → **%** 버튼을 누릅니다 — 이미 % 형식인 칸에 누르면 소수 자리가 없어져 `12%`로 보입니다.
    68. **D65–D67**에 '같음/다름'이 저절로 나옵니다.
    69. '다름'이면 아래 질문으로 원인을 찾아 **E열**(다르면 이유)에 적습니다. `03_EDA` ①의 진단 목록이 힌트입니다.
        - 분모(행 수)가 같은가? AI는 몇 행을 읽었다고 했나?
        - 같은 바이어가 두 번 세어지지 않았나? (`buyer_id`가 같은 행)
        - 숫자가 아닌 연체일을 AI와 엑셀이 각각 어떻게 처리했나?
        - '미분류'·'확인필요' 결제조건을 AI는 어느 코드에 넣었나? (표0 매핑표와 내 `00_코드표` 비교)
        - '연체'의 정의(연체일 > 0)와 비율의 분모가 같은가?
    70. 원인이 짐작되면 AI에게 확인시킵니다: `엑셀에서는 ○○이 △△로 나왔다. (결제방식 코드) 그룹에 들어간 buyer_id 목록과 각 행의 연체일을 보여라.`
    71. (선택) 68–69행 '내가 고른 지표'에 피벗②의 1위 나라 연체 비율처럼 비교하고 싶은 숫자를 하나 더 적습니다.

    !!! question "AI 숫자와 엑셀 숫자가 다르면 누가 틀린 걸까요?"
        둘 다 틀릴 수 있습니다. 정답을 고르는 것이 아니라 **왜 다른지 원인을 찾아 적는 것**이 오늘의 일입니다.

    !!! note "비율의 분모를 맞추세요"
        P1-4는 연체 비율을 **'확인필요'(연체일이 숫자가 아닌 행)를 뺀 분모**로 계산합니다. 위 방법(피벗② 총합계 · AVERAGEIFS)도 같은 정의입니다.
        템플릿 70행 안내처럼 피벗①(행 합계 비율)의 1-30~91+를 더해 읽으면 '확인필요' 행까지 분모에 들어가 조금 작게 나옵니다 — 그 차이도 '분모가 다르다'는 원인으로 적으면 됩니다.


    **5단계 — 인사이트 3개 (`03_EDA` ④)**

    72. `03_EDA` **74–76행**에 인사이트 3개를 씁니다: B열에 **숫자가 들어간 한 문장**, E열에 근거(어느 피벗의 어떤 숫자), F열에 그래서 무엇을 할지(다음 행동·질문).
        예시 형식: "결제방식 ○○ 바이어 N곳 중 M곳(xx%)이 연체(피벗①) → ○○ 바이어는 다음 선적 전에 미수금부터 확인한다."
    73. 세 문장을 점검합니다 — 상관을 원인으로 단정하지 않았나? 표본이 작은 숫자에 '표본 작음'을 붙였나? 결함이 섞인 숫자에 '원천 기준'이라고 밝혔나?
    74. ++ctrl+s++ 로 저장합니다.

=== "🔵 Standard"

    **내 데이터(익명화) 또는 페르소나로 같은 피벗 만들기** · Basic 3단계까지 끝낸 뒤 합니다. 둘 중 하나를 고르세요.

    **A. 내 회사 데이터로 (익명화 체크리스트 통과본만)**

    1. 내 데이터가 [익명화 체크리스트](../setup.md#byod)를 **모두** 통과했는지 다시 확인합니다.
    2. 익명화했더라도 **무료 AI에는 올리지 않습니다**(데이터 위생 2원칙). AI 단계는 회사가 허용한 AI(학습 꺼짐)에서만 하거나 건너뜁니다. P1-3을 쓴다면 `[맥락]` 줄의 회사 설명과 기준일을 내 데이터에 맞게 고칩니다.
    3. 내 파일의 시트를 Basic 22–24번처럼 템플릿으로 복사합니다(`tbl_codes`가 있는 같은 파일 안에 있어야 수식이 됩니다). 복사한 시트의 표 안 아무 셀 → ++ctrl+t++ → **머리글 포함** → **확인** → 표 이름을 `tbl_my`로 바꿉니다.
    4. 내 결제조건 표기도 `00_코드표`에 한 줄씩 추가해 코드 7종으로 바꿉니다. [새 열 만들기](#new-columns)의 수식에서 `[@payment_terms_raw]`·`[@max_dpd_days]` 자리만 내 표의 열 이름으로 바꿉니다.
    5. 연체일 열이 있으면 같은 수식으로 `dpd_num` · `aging_bucket` · `is_overdue`를 만듭니다.
    6. Basic 45–64번처럼 피벗 3개를 만듭니다. 위치는 `04_피벗` 아래쪽 빈 곳(예: A82부터)이나 새 시트로 하고, 표/범위는 `tbl_my`를 고릅니다. 국가 대신 권역·업종처럼 내 데이터에 있는 열을 써도 됩니다.
    7. 한빛정밀 피벗과 내 피벗을 나란히 놓고 '우리 회사는 어디가 다른가' 한 줄을 `03_EDA`에 적습니다.

    **B. 페르소나 렌즈로 (내 데이터가 없거나 반출이 안 될 때)**

    1. [페르소나 카드 4종](../ax-project.md#personas) 중 나와 가장 가까운 하나를 고릅니다.
    2. 한빛정밀 `tbl_buyers`로 그 페르소나의 관점에서 **피벗④**를 하나 더 만듭니다(`04_피벗` 아래쪽 빈 곳, 예: A82).

        | 페르소나 | 피벗④ 예시 | 이렇게 읽는다 |
        |---|---|---|
        | 페르소나 A 수출 중소 무역사무 | 행 `payment_method` · 값 `dpd_num`(평균) · `buyer_id`(개수) | 어느 결제조건의 연체가 길게 가나 → 독촉 우선순위 |
        | 페르소나 B 여신·채권 관리 | 행 `ksure_insured` · 열 `aging_bucket` · 값 `buyer_id`(개수) | 보험에 든 바이어 중 연체가 길어진 곳 → 추가 선적 전 확인 목록 |
        | 페르소나 C 공공조달 계약 | 행 `buyer_type` · 열 `aging_bucket` · 값 `buyer_id`(개수) | 공공 바이어(UN·MDB·정부)와 민간의 결제 패턴 차이 |
        | 페르소나 D 재무·기획 | 행 `region` · 열 `payment_method` · 값 `buyer_id`(개수, 행 합계 비율) | 권역별 결제조건 구성 → 경영진 보고 한 줄 |

    3. 피벗④에서 읽은 것을 그 페르소나의 말투로 `03_EDA`에 한 줄 씁니다.

    **(선택) Orange로 연체일 분포 보기** — Basic 3단계의 새 열 4개를 만든 뒤에 합니다.

## 흔한 오류와 해결 {#troubleshooting}

| # | 증상 | 원인 | 해결 |
|---|---|---|---|
| 1 | X2에 수식을 넣으니 **#NAME?** | XLOOKUP이 없는 엑셀(2019·2016 이하) | [대안 수식](#xlookup-alt)(INDEX·MATCH 또는 VLOOKUP)을 씁니다 |
| 2 | 수식에 `tbl_codes` 오류(#REF!·#NAME?) | `00_코드표`가 없는 파일에서 작업 중이거나, 표 이름이 다르다 | 템플릿 파일 안에서 작업하는지 확인 → `00_코드표`의 표를 클릭 → **테이블 디자인** → 표 이름이 `tbl_codes`인지 확인 |
| 3 | 거의 모든 행이 '미분류' | 열 이름 오타, 또는 코드표 `raw_upper` 칸이 대문자가 아님 | 수식의 `[raw_upper]`·`[payment_method]` 철자를 확인. 추가한 줄의 B칸에 `=UPPER(TRIM([@raw_variant]))`가 있는지 확인 |
| 4 | 코드표에 추가했는데도 '미분류'가 그대로 | 원문을 옮길 때 글자가 달라졌다(공백·오탈자), 또는 표 바로 아래가 아니라 한 줄 띄워 적어 표 밖에 있다 | 원문을 수식 입력줄에서 그대로 복사해 다시 붙입니다. 추가한 줄이 표(줄무늬) 안에 들어갔는지 확인 |
| 5 | ++ctrl+t++ 를 눌렀는데 범위가 이상하다 | 빈 셀을 선택한 채 눌렀다 | A2 셀을 클릭한 뒤 다시 ++ctrl+t++. 범위가 `$A$1:$W$154`인지, **머리글 포함**이 체크됐는지 확인 |
| 6 | 2행에만 수식이 들어가고 아래가 비었다 | 표 밖에 수식을 넣었다(표가 넓어지지 않음) | 먼저 1행에 열 이름을 넣어 표를 넓힌 뒤 2행에 수식. 또는 수식 칸 옆 ⚡ → **이 수식으로 이 열의 모든 셀 덮어쓰기** |
| 7 | 피벗 값이 '개수'로만 나오고 평균이 안 된다 | 빈칸(글자)이 섞인 열이라 엑셀이 기본값을 '개수'로 잡았다 | 값 ▼ → **값 필드 설정** → **평균**. 연체일은 원본 `max_dpd_days` 대신 `dpd_num`을 씁니다 |
| 8 | 새로 만든 열이 피벗 필드 목록에 없다 | 피벗을 만든 뒤에 열을 추가했다 | 피벗 안 클릭 → **피벗 테이블 분석** → **새로 고침**. 그래도 없으면 **데이터 원본 변경** → `tbl_buyers` |
| 9 | 코드표에 줄을 추가했는데 피벗에 '미분류'가 남아 있다 | 피벗은 자동으로 다시 계산되지 않는다 | 피벗 안 클릭 → **피벗 테이블 분석** → **모두 새로 고침** |
| 10 | 피벗① 각 행의 합이 100%가 아니다 | '행 합계 비율'이 아니라 '총합계 비율'을 골랐다 | 값 필드 설정 → 값 표시 형식 → **행 합계 비율** |
| 11 | '피벗 테이블 보고서는 겹칠 수 없습니다' | 피벗이 커지며 아래 피벗과 겹쳤다 | **피벗 테이블 분석** → **피벗 테이블 이동** → 더 아래 빈칸 |
| 12 | 피벗②에 같은 나라가 두 줄로 나온다 | `country`(원천 표기) 열을 썼다 | 행에 `country_code`를 씁니다 |
| 13 | '상위 10'인데 10개국보다 많이 나온다 | 10위 비율이 같은 나라가 여럿(동점) | 정상입니다. 동점임을 메모합니다 |
| 14 | CSV를 열었더니 한글이 깨진다 | 엑셀이 인코딩을 잘못 골랐다 | `.xlsx` 파일을 씁니다. CSV를 꼭 써야 하면 [FAQ의 CSV 한글 깨짐](../faq.md#q-csv) |
| 15 | AI가 "정리한 파일"을 만들어 버렸다 | 진단과 수정을 한 번에 시켰다 | 받지 않습니다. `고친 결과는 버리고, 원본 그대로 센 숫자로 다시 진단만 하라.` |
| 16 | Orange Box Plot에 결제방식 그룹이 안 보인다 | 열이 글자(text)로 읽혔다 | File 위젯에서 `payment_method`의 Type을 **categorical**로 바꾸고 **Apply** |
| 17 | 코드표에 추가했는데 '미분류' 필터 화면에 그 행이 그대로 있다 | 필터는 값이 바뀌어도 저절로 다시 걸러지지 않는다 | 그 행의 `payment_method`가 코드로 바뀌었으면 정상. **데이터** → **다시 적용** |
| 18 | 붙여 넣을 때 '병합된 셀의 일부를 변경할 수 없습니다' | 붙일 표가 템플릿 자리(① 21행까지 · ② 59행까지)보다 길다 | ① AI에게 14줄 이내로 줄여 달라고 한다(8번) · ② 긴 표는 새 시트에 붙인다(18번) |
| 19 | 피벗②를 만들 때 '…이미 데이터가 있습니다. 바꾸시겠습니까?' | 상위 10 필터 전에는 나라가 모두 보여 61행 안내 글까지 길어진다 | **확인** → 60번에서 상위 10 필터를 걸면 다시 짧아진다 |
