## 파일 받기 {#files}

**내 저장소를 만들었다면 받을 것이 없습니다.** 오늘 쓰는 파일은 과정 템플릿에 이미 들어 있어서 `data/day1/` · `labs/day1/` 아래에 있습니다. 저장소 없이 채팅 경로로 하는 사람이나, 파일 하나가 필요한 사람은 아래 표에서 받습니다.

1. 아래 표 맨 위 **`day1_files.zip`** 줄의 **받기**를 누릅니다. 오늘 쓰는 파일이 전부 들어 있습니다.
2. 파일 탐색기(Mac: Finder)에서 **다운로드** 폴더를 엽니다.
3. 받은 zip 파일을 마우스 오른쪽 버튼으로 누르고 **모두 압축 풀기** → **압축 풀기**를 누릅니다. (Mac: zip 파일을 더블클릭)
4. 압축이 풀린 창에 보이는 **`D1`** 폴더를 바탕화면으로 끌어다 놓습니다.
5. `D1` 폴더를 열어 확인합니다. 보고서 발췌(`irobot.md` 같은 `.md` 파일)는 **`D1` → `reports`** 폴더에, 나머지 파일은 `D1` 바로 안에 있습니다.

필요한 파일만 하나씩 받아도 됩니다. 그럴 때는 바탕화면에 `D1` 폴더를 직접 만들고, 받은 파일을 그 폴더로 옮깁니다.

- **회사 실데이터 · 개인정보는 올리지 않습니다 — 익명화본도.** AI 서비스의 '모델 개선(학습)' 설정은 끄고 시작하고([사전 준비 — AI 학습 설정 끄기](../setup.md#ai-training)), 내 저장소는 공개이므로 키 · 비밀번호 · 회사 자료는 커밋하지 않습니다.

## 오늘의 결과물과 제출 {#submit}

오늘 결과물은 **일곱 묶음, 파일로는 아홉 가지**입니다. 결과 파일은 `workbench/day1/outputs/`에, 노트북은 `workbench/day1/notebooks/`에 둡니다.

| 결과물 | 파일 | 점검 기준 |
|---|---|---|
| 작업 환경 | 내 저장소 · `CLAUDE.md` | 커밋 2개 이상, 메시지에 '왜' 줄 |
| 위험 신호 표 | `d1_signals_halden.md` | 인용 2개 일치 · 불일치 표시 |
| 재무비율 | `d1_ratios_halden.md` | 공식 · 대입값 · 두 AI 대조 |
| 품질 보고서 · 변수 정의서 | `d1_quality_report.md` · `d1_data_dictionary.md` | 재무 지표 4개 정의 포함 |
| 코드표 | `d1_code_table.csv` | '검토 필요' 0행 |
| EDA 노트북 · 차트 · 메모 | `notebooks/d1_eda.ipynb` · `charts/*.png` · `d1_eda_notes.md` | 해석 3줄 · 피벗 대조 1개 |
| 현안 정의서 | `d1_issue_definition.md` | 결제방식별 근거 숫자 |

- **제출 = push**입니다. 실습 A-1 ⑤에서 내 저장소 주소를 한 번 제출하면, 이후 push한 커밋을 강사가 저장소 주소 목록으로 확인합니다. 제출 폼 링크는 당일 [사이트 홈](../index.md) 공지와 오픈채팅에 있습니다.
- 점검 기준은 **'파일이 있다'가 아니라 검증한 흔적**입니다 — 인용 2개 일치 표시, '검토 필요' 0행, 피벗 대조 1개처럼요.
- 현안 정의서의 '내 업무라면' 칸과 메모에는 **회사 이름 · 실명 · 실제 숫자를 쓰지 않습니다.** 저장소가 공개입니다.
- 다 끝내지 못했어도 그대로 push하세요. 내일 아침 **첫 명령 하나**(`uv run python tools/get_day_files.py 2`)로 2일차 시작 파일을 받아 모두 같은 출발점에서 시작합니다.
- 17:00에는 이 표를 다시 띄우고 흔한 실수를 함께 짚습니다. 정답 파일은 그때 강사 화면으로만 보여 드립니다.

## 함께하는 규칙 {#rules}

- **1:1 순회**: 강사가 실습 동안 한 분씩 2–3분 확인합니다. 막히면 손을 들거나 빨간 표시를 올립니다.
- **짝과 한 화면**: 막히면 짝과 한 화면을 같이 봐도 좋습니다. 단, 정답을 베끼는 것이 아니라 **AI가 놓친 문제를 서로 찾아 견주는** 용도입니다.
- **새 일 = 새 대화**: 한 대화에서는 문서(파일) 하나만 다룹니다. 같은 문서로 이어 가는 프롬프트(A1 → A2)는 같은 대화에, 다른 문서나 다른 일은 새 대화에서 시작합니다.
- **허락 창은 읽고 승인**: 무엇을 · 어디에 · 지우는지 세 가지를 읽고 `1 Yes`. 파일 삭제 · 강제 push · `git reset --hard`는 거절합니다.
- **현장 이야기를 들려 주세요**: 실습하다가 "우리 회사에서는 이렇게 한다"는 이야기가 나오면 말씀해 주세요 — 6일차 도입 기획의 재료가 됩니다.

!!! success "오늘의 습관 네 가지"
    1. AI에게 **근거를 요구**한다 — AI가 준 **문장**은 원문에서 ++ctrl+f++ 로 찾는다.
    2. AI가 준 **숫자**는 공식 · 대입값 · 계산 코드를 받아 다시 확인한다 — 검증 전까지는 초안이다.
    3. **원본은 그대로 두고, 고치기 전에 진단부터** — AI에게도 "수정 금지"라고 말한다.
    4. **허락 창은 읽고 승인**하고, 결과는 **커밋**으로 남긴다.
