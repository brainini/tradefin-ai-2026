# FAQ · 트러블슈팅

막히면 먼저 노트북 위에 **빨간 표시**(스티커 등)를 올리고, 아래에서 증상을 찾아보세요. 5분 안에 안 풀리면 손을 들어 주세요.
각 실습 페이지 아래에도 그 실습에서 자주 나오는 오류 표가 있습니다(예: 1일차 [실습 A](day1/lab-a.md#troubleshooting) · [실습 B](day1/lab-b.md#troubleshooting)). 설치와 로그인 문제는 [사전 준비 → 자주 막히는 곳](setup.md#stuck)에도 있습니다.

## 계정 · 접속

### Claude 가입 때 문자 인증이 안 돼요 {#q-claude-sms}

Claude는 휴대폰 **문자(SMS) 인증**이 필요합니다. 인터넷 전화(VoIP)·가상번호·유선전화 번호는 받지 않고, 한 번호로 최대 3개 계정까지만 만들 수 있습니다.
본인 휴대폰 번호로 다시 시도하세요. 오늘 안에 해결이 안 되면 **ChatGPT**로 채팅 경로 실습을 하면 됩니다([1일차 실습 A의 대체 경로](day1/lab-a.md#chat-path) · [실습 B의 채팅 경로](day1/lab-b.md#chat-path)). Claude Code는 Claude 계정이 있어야 쓸 수 있습니다.

### Claude Code 로그인이 안 되거나 "무료 요금제는 쓸 수 없다"고 나와요 {#q-claude-code-login}

Claude Code는 **Pro 이상 구독, 과정에서 나눠 주는 Team 좌석, Console(API) 계정** 중 하나가 있어야 합니다. 무료(Free) 요금제로는 로그인되지 않습니다.

1. 로그인 화면에서 구독 계정은 **Claude.ai Subscription**, API 계정은 **Anthropic Console**을 고르고 브라우저에서 승인한 뒤 VS Code로 돌아옵니다.
2. 돌아오지 않으면 브라우저에 표시된 코드를 Claude Code 패널에 붙여 넣습니다.
3. 구독 중인데 API 요금이 청구된다면 환경변수 `ANTHROPIC_API_KEY`가 설정돼 있는지 봅니다([사전 준비 0-4](setup.md#claude-code)).
4. 끝내 안 되면 **채팅 경로**(claude.ai · ChatGPT + GitHub 웹 화면)로 같은 실습을 합니다 → [1일차 실습 A](day1/lab-a.md#chat-path).

### 회사 노트북에서 AI 사이트나 GitHub이 막혀 있어요 {#q-blocked}

1. 휴대폰 핫스팟으로 바꿔도 회사 보안 프로그램이 막을 수 있습니다 — 회사 규정을 어기면서 우회하지 마세요.
2. 개인 노트북이 있으면 그것을 씁니다.
3. 브라우저만 열리면 **Codespaces**(브라우저 안의 VS Code)로 같은 작업실을 쓸 수 있습니다 → [사전 준비 → Codespaces](setup.md#codespaces).
4. 없으면 옆 사람과 **한 화면으로 페어**(드라이버·내비게이터)를 합니다. 엑셀 단계는 내 노트북에서 해도 됩니다.

### 과정 사이트가 안 열리거나 글꼴이 이상해요 {#q-site}

글꼴(Noto Sans KR)은 Google Fonts에서 받아 오는데, 회사 망에서 막히면 기본 글꼴로 보입니다 — 내용은 같으니 그대로 쓰면 됩니다.
사이트 자체가 안 열리면 강사가 오픈채팅·USB로 파일을 나눠 드립니다.

## VS Code · Claude Code

### Claude 아이콘(Spark)이 안 보이거나 패널이 안 열려요 {#q-claude-icon}

파일을 하나 엽니다 → VS Code를 업데이트합니다 → ++ctrl+shift+p++ → `Developer: Reload Window` → 폴더 신뢰 창에서 **Yes, I trust the authors**를 눌렀는지(제한 모드가 아닌지) 봅니다. 폴더를 신뢰하지 않으면 Claude Code 확장이 동작하지 않습니다.

### 모드가 Auto로 시작하거나, 계획 승인 창에서 `use auto mode`를 눌러 버렸어요 {#q-mode}

시작 모드는 저장소 설정으로 정할 수 없어 PC마다 다릅니다. **입력창 아래 모드 표시**를 눌러 **Manual**(또는 Plan)로 바꿉니다. 새 대화를 열 때마다 한 번 확인하는 것이 좋습니다.
계획 승인 창에서는 맨 위 `use auto mode`가 미리 골라져 있어 Enter만 치면 눌립니다 — **마우스로 `2 Yes, and manually approve edits`**를 고르세요. 이미 눌렀다면 괜찮습니다. 다음부터 다시 고르고, 만들어진 파일은 소스 제어의 diff로 읽어 봅니다.

### 허락 창이 너무 자주 떠요 {#q-permission}

정상입니다. 무엇을 · 어디에 · 지우는 것이 있는지 읽고 `1 Yes`를 누르는 것이 이 과정의 안전장치입니다. 모르는 명령이면 `2 No`로 거절하고 무슨 명령인지 물어보세요.
파일 삭제 · 강제 push · `git reset --hard`처럼 되돌릴 수 없는 명령은 거절합니다. 승인 범위를 넓히는 선택은 강사가 안내한 뒤에만 합니다.

### Claude가 `CLAUDE.md`의 규칙을 안 지켜요 {#q-claudemd}

`CLAUDE.md`는 AI가 먼저 읽는 **지침**이지 강제 장치가 아닙니다. 대화가 길어지면 앞의 지시를 놓치기도 합니다.

- 중요한 규칙은 프롬프트에도 한 줄 더 적습니다("원본 수정 금지", "결과는 `outputs` 폴더에").
- 일이 바뀌면 **새 대화**를 엽니다.
- 규칙을 어긴 결과는 커밋하지 말고, 어긴 곳을 짚어 다시 시킵니다.

### 사용 한도에 걸렸다고 나와요 {#q-usage-limit}

구독은 **사용 한도**가 있고, 한도는 토큰으로 셉니다. 긴 파일을 통째로 붙이거나 같은 대화를 오래 이어 갈수록 빨리 찹니다.

1. 안내 메시지에 적힌 풀리는 시각을 확인합니다.
2. 새 일은 새 대화에서 시작하고, 필요한 파일만 `@`로 지정합니다.
3. 그동안은 짝의 화면을 함께 보거나 ChatGPT · Claude 웹의 채팅 경로로 진행합니다. 강사에게도 알려 주세요.

### 노트북 커널 목록에 `.venv`가 없어요 {#q-kernel}

`uv sync`를 먼저 한 뒤 ++ctrl+shift+p++ → `Developer: Reload Window`. 노트북 오른쪽 위 **Select Kernel → Python Environments → `.venv`(3.13)**를 고릅니다. 그래도 안 되면 노트북 대신 스크립트(`.py`)로 같은 일을 시킵니다 — 점검 기준은 같습니다.

## Git · GitHub · uv

### `git pull`을 했는데 오늘 파일이 안 와요 {#q-pull}

내 저장소는 과정 저장소를 **템플릿**으로 만든 새 저장소라서 원본과 이력이 이어져 있지 않습니다. 그래서 `git pull`로는 새 파일이 오지 않습니다. 매일 아침(그리고 공개 시각마다) 이 명령을 실행하세요.

```bash
uv run python tools/get_day_files.py 3    # 3 = 오늘 일차
```

이미 있는 파일은 덮어쓰지 않고, 아직 공개 전이면 "공개 전"이라고 알려 줍니다. 공개 시각이 지난 뒤 같은 명령을 다시 실행하면 새로 올라온 파일만 더 받습니다 → [사전 준비 0-8](setup.md#daily-files).

### push가 거부되거나 로그인을 물어요 {#q-push}

VS Code 왼쪽 아래 **계정 아이콘**에서 GitHub에 로그인합니다. `GH007 … private email` 오류가 나면 `git config --global user.email`을 GitHub의 noreply 주소로 바꾸고 다시 커밋합니다([사전 준비 0-2](setup.md#git)).

### 파일이 커밋 목록(소스 제어)에 안 나타나요 {#q-gitignore}

`.gitignore`가 막고 있을 수 있습니다. 키 · `.env` · `private/` 폴더는 일부러 막혀 있고, 결과 파일은 `workbench/dayN/outputs/`에 있어야 보입니다. 터미널에서 `git check-ignore -v 파일이름`을 치면 어느 줄이 막는지 알려 줍니다. 5일차에 배포용 데이터를 일부러 올릴 때는 실습 페이지가 안내하는 이름만 `git add -f`로 더합니다.

### PR을 만들었는데 병합 버튼이 안 눌려요 / 충돌이 났어요 {#q-conflict}

- **충돌(conflict)**은 같은 줄을 서로 다르게 고쳤다는 뜻입니다. 오류가 아닙니다. Claude Code에게 충돌 표시(`<<<<<<<`)가 있는 파일을 열어 **양쪽을 읽고 어떻게 합칠지 설명한 뒤 합쳐 달라**고 하고, 합친 결과를 diff로 읽고 확인합니다 → [2일차 프롬프트 B6](prompts/day2.md#b6).
- 병합 버튼은 **검사(Actions)가 빨간 ✗**이거나 충돌이 있으면 막힐 수 있습니다. 먼저 ✗의 원인을 읽습니다.
- 병합은 **사람이 GitHub 화면에서** 누릅니다(리뷰 한 줄을 받은 뒤).

### `uv sync`나 `uv run`이 실패해요 {#q-uv}

처음에는 패키지를 받느라 몇 분 걸릴 수 있습니다(교실 Wi-Fi가 붐비면 더). 회사 망이 pypi.org · github.com을 막으면 개인 노트북이나 [Codespaces](setup.md#codespaces)로 갑니다. 터미널에서는 `python` 대신 항상 **`uv run python …`**으로 실행합니다 → [사전 준비 0-10](setup.md#stuck).

## AI 도구

### ChatGPT에 파일이 더 안 올라가요 (업로드 한도) {#q-upload-limit}

ChatGPT **무료** 계정은 파일 업로드가 **하루 3개**입니다. 실습은 그보다 많이 올리므로 **Claude**로 바꾸세요.
ChatGPT를 꼭 쓰려면 강사 공용 프로젝트(초대 링크) 또는 유료 개인 계정을 씁니다.

### 파일 업로드가 실패해요 (크기·형식) {#q-upload-fail}

| 도구 | 한도(2026-09 확인, 바뀔 수 있음) | 안 될 때 |
|---|---|---|
| Claude | 파일당 30MB | 과정 파일은 대부분 1MB 안팎이라 크기 문제는 드뭅니다. 로그인 상태를 확인하세요 |
| ChatGPT 무료 | 하루 3개 | 다른 도구로 바꿉니다 |

`.md` 파일이 '지원하지 않는 형식'으로 나오면, 파일을 메모장으로 열어 전체 복사(++ctrl+a++ → ++ctrl+c++)한 뒤 입력창에 붙여 넣어도 됩니다. `.xlsx`가 안 되면 같은 내용의 `.csv`를 올립니다.

### AI가 준 인용문이 원문에서 안 찾아져요 {#q-quote}

1. 인용 전체 대신 **중간의 짧은 단어 4–5개**로 ++ctrl+f++ 를 다시 합니다(줄바꿈·따옴표 차이를 피하기 위해).
2. 그래도 없으면 AI가 문장을 바꿨거나 지어낸 것입니다. 표의 확인 열에 **불일치**를 적고 **A1 재질문**("표의 {N}번 행 인용을 원문에서 찾지 못했다. 원문 문장을 글자 그대로 다시 인용하고, 없으면 '명시되지 않음'으로 바꿔라.")으로 그 행만 다시 묻습니다. 다시 물은 결과는 같은 표에 적습니다([1일차 실습 A ⑦](day1/lab-a.md#a2-quotes)).
3. 이것은 실패가 아니라 **발견**입니다. 실습의 목적이 바로 이것을 찾는 것입니다.

### AI가 그럴듯한 숫자를 지어냈거나, 두 AI의 숫자가 달라요 {#q-numbers}

숫자는 **공식 · 대입값 · 계산 코드**를 함께 받아 직접 다시 확인합니다. 달라지는 흔한 원인은 당기 · 전기 열을 바꿔 쓴 것, 단위(천 단위 · 백만 단위)와 기간(365일)이 다른 것, 합계에 넣는 항목이 다른 것입니다. 검증 전까지 AI 숫자는 초안입니다.

### AI가 앞에서 정한 형식을 잊거나, 같은 질문에 답이 매번 달라요 {#q-context}

- 대화가 길어지면 AI는 앞부분을 놓칩니다(작업 책상이 넘침). 일이 바뀌면 **새 채팅**을 엽니다.
- AI는 '그럴듯한 다음 말'을 고르는 방식이라 같은 질문에도 답이 조금씩 다릅니다. 그래서 **근거(인용·위치·코드)**를 함께 받고 확인합니다.
- 긴 작업을 이어 가야 하면 `지금까지 정한 조건과 결론을 짧게 정리해 줘` → 새 채팅에 그 요약을 붙여 넣고 시작합니다.

### AI 답의 표를 엑셀에 붙이면 한 칸에 몰려요 {#q-paste}

AI 화면의 '복사' 버튼은 표를 글자(마크다운)로 복사할 때가 많습니다.

1. 표를 **마우스로 끌어 선택**한 뒤 ++ctrl+c++ 를 누르고 엑셀에 붙여 넣습니다.
2. 그래도 안 되면 AI에게 `탭으로 구분된 표로 다시 줘`라고 한 뒤 붙여 넣습니다.
3. 색이 사라지거나 열이 어긋나면 붙일 칸을 마우스 오른쪽 버튼으로 누르고 **붙여넣기 옵션 → 대상 서식에 맞추기**를 고릅니다. 머리글 줄까지 붙었으면 그 줄만 지웁니다.

### 화면의 모델 이름이 안내와 달라요 {#q-model-names}

정상입니다. 모델 이름과 메뉴는 자주 바뀌어서(개강일에도 바뀝니다) 안내는 이름보다 **계층(최상위 · 주력 · 경량)과 일의 종류**로 적었습니다.
먼저 주력 계층으로 하고, 결과가 이상하거나 조건이 복잡하면 생각을 더 하는 쪽(추론 · effort)으로 바꿔 비교하세요.

## 엑셀 · CSV

### CSV를 열면 한글이 깨져요 {#q-csv}

과정 CSV는 UTF-8(BOM 포함)이라 보통 바로 열립니다(1일차 실습 A-1 ①의 연습 파일 `d1_encoding_test.csv`만 일부러 BOM 없이 저장해 깨지게 했습니다). 깨지면:

1. 가능하면 같은 내용의 **`.xlsx`** 파일을 씁니다.
2. CSV를 써야 하면 엑셀 빈 통합 문서에서 **데이터** 탭 → **텍스트/CSV에서**를 누릅니다.
3. 파일을 고른 뒤 '파일 원본'을 **65001: 유니코드(UTF-8)**로 바꾸고 **로드**를 누릅니다.
4. 내가 CSV로 저장할 때는 파일 형식에서 **CSV UTF-8(쉼표로 분리)**을 고릅니다(그냥 'CSV'로 저장하면 다른 프로그램에서 한글이 깨질 수 있습니다).

### XLOOKUP이 없어요 (#NAME?) {#q-xlookup}

Excel 2019·2016 이하에는 XLOOKUP이 없습니다. [1일차 실습 B ⑤의 대안 수식](day1/lab-b.md#xlookup-alt)(INDEX·MATCH 또는 VLOOKUP)을 쓰면 결과가 같습니다.
버전 확인: **파일** → **계정** → **Excel 정보**. 웹용 Excel(office.com)에는 XLOOKUP이 있습니다.

### 피벗 숫자가 AI(노트북) 숫자와 달라요 {#q-pivot-vs-ai}

**정상이고, 1일차 실습의 핵심입니다.** 둘 다 틀릴 수 있습니다. 아래 순서로 원인을 찾아 `d1_eda_notes.md`의 '손 검산' 절에 적습니다.

1. **분모**: AI는 몇 행을 읽었나? 엑셀 표는 몇 행인가?
2. **중복**: 같은 `buyer_id`가 두 번 세어지지 않았나?
3. **숫자가 아닌 칸**: 연체일이 글자인 칸을 AI는 어떻게 처리했나(0으로? 빼고?), 엑셀은 빈 칸으로 뒀다.
4. **결제조건 매핑**: AI의 코드표와 내가 만든 코드표(B-1 ②)가 같은가? '미분류'·'검토 필요'를 어디에 넣었나?
5. **정의**: '연체 = 연체일 > 0'으로 같은가?

그다음 AI에게 `엑셀에서는 ○○이 △△로 나왔다. 네 계산과 다른 이유를 코드로 확인해 줘`라고 묻습니다.

### 피벗에서 새 열이 안 보이거나, 합계·평균이 안 돼요 {#q-pivot}

- 새 열이 필드 목록에 없으면: 피벗 안 클릭 → **피벗 테이블 분석** → **새로 고침**. 그래도 없으면 **데이터 원본 변경**으로 범위를 새 열까지 넓힙니다.
- 값이 '개수'로만 나오면: 값 ▼ → **값 필드 설정** → **합계** 또는 **평균**. 글자가 섞인 열은 엑셀이 '개수'를 기본으로 잡습니다.
- '피벗 테이블 보고서는 겹칠 수 없습니다'가 뜨면 피벗 안 클릭 → **피벗 테이블 분석** → **피벗 테이블 이동**으로 더 아래 빈칸을 고릅니다.

### 파일을 열면 노란 띠(제한된 보기)가 떠요 {#q-protected-view}

인터넷에서 받은 파일이라 엑셀이 읽기 전용으로 연 것입니다. **편집 사용**을 누르세요. 과정 엑셀 파일에는 매크로가 없습니다.

## 데이터 · 제출

### 실수로 회사 실데이터를 AI나 저장소에 올렸어요 {#q-leak}

1. 그 대화를 바로 **삭제**합니다.
2. 강사·도우미에게 알립니다(비난하지 않습니다. 기록만 합니다).
3. 저장소에 커밋했다면 파일을 지우는 것으로 끝나지 않습니다(이력에 남습니다). **바로 알리고**, 키였다면 키부터 교체합니다.
4. 가상 데이터로 바꿔 계속합니다. 다음부터는 [데이터 위생 5원칙](setup.md#hygiene)과 [익명화 체크리스트](setup.md#byod)를 먼저 봅니다.

### 압축을 풀었는데 보고서 파일이 안 보여요 {#q-zip}

(저장소 없이 채팅 경로로 하는 분이 `day1_files.zip`을 받은 경우입니다.)

1. 보고서 발췌(`halden_fictional_annual_report.md` · `irobot.md` · `plug_power.md` 등)는 `D1` 폴더 안의 **`reports`** 폴더에 있습니다.
2. `D1` 폴더 안에 또 `D1` 폴더가 있으면(두 겹), 안쪽 `D1` 폴더를 바탕화면으로 끌어다 놓고 빈 바깥 폴더는 지웁니다.
3. zip 파일을 더블클릭해 안을 들여다보기만 한 상태에서 엑셀 파일을 열면 임시 폴더에서 열려, 저장한 내용이 사라질 수 있습니다. 꼭 마우스 오른쪽 버튼 → **모두 압축 풀기**로 푼 뒤 `D1` 폴더의 파일을 엽니다.

순서는 [Day1 → 파일 받기](day1/index.md#files)에 있습니다.

### 보고서 발췌(.md) 파일은 어떻게 여나요? {#q-md}

글자만 들어 있는 파일입니다. 파일을 마우스 오른쪽 버튼으로 누르고 **연결 프로그램 → 메모장**(Mac: **다음으로 열기 → 텍스트 편집기**)을 고르거나, 크롬 창에 끌어다 놓으면 열립니다.
사이트에서 눌렀을 때 화면에 글자만 뜨면 **마우스 오른쪽 버튼 → 다른 이름으로 링크 저장**으로 받습니다.

### 제출은 어떻게 하나요? {#q-submit}

- **1–5일차**는 파일을 따로 내지 않고 **내 저장소에 push**(2일차부터는 **PR**)하는 것이 제출입니다. 1일차 실습 A-1 ⑤에서 내 저장소 주소를 한 번 제출하면, 이후 push한 커밋과 PR을 강사가 저장소 주소 목록으로 확인합니다. 결과 파일은 `workbench/dayN/outputs/`에 둡니다 → [Day1 → 산출물과 제출](day1/index.md#submit).
- **6일차**는 팀이 릴리스 `v1.0` 링크를, 개인이 도입 기획서 · KPI · ROI를 비공개 폼으로 냅니다 → [6일차 제출](day6/submit.md).
