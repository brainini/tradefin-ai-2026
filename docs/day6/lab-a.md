## Step 1 · 카드 해석 · 변수표 (09:31–09:50) {#a-card}

1. **카드 개봉 신호**가 오면 종이 카드를 엽니다. 앞면에 상황과 답해야 할 질문 5개, 뒷면에 실제로 있었던 일(앵커)과 용어 상자가 있습니다. 상황과 숫자는 교육용 가정이고 뒷면 앵커만 실제 사실입니다. **3분** 읽습니다.
2. 저장소 관리자는 위 [입력 파일](#files)의 두 줄을 실행하고, 우리 카드 → `cards/`, 팀 팩 → `data/input/`로 복사해 커밋합니다(`git add cards data/input`). 막히면 [6일차 개요](index.md#files)의 `day6_files.zip`을 받아 같은 자리에 둡니다. [RA](../prompts/day6.md#ra) 프롬프트로 Claude Code에게 시켜도 됩니다(복사와 커밋 명령은 읽고 승인).
3. 전원이 카드를 **ChatGPT 또는 Claude**에 붙여 "바뀌는 변수 6종(PD · LGD · EAD · 지연일 · 환율 · 결제조건) 중 무엇이, 어느 파일의 어느 열에서, 얼마나 바뀌는지" 표 초안을 만들게 합니다.

    | 카드 변수 | 대상 파일 · 열 | 바뀌는 값 | 영향 바이어 수 | 담당 |
    |---|---|---|---|---|
    | (예) PD | `d6_{카드}_scored.csv`의 `pd_30d` | × `pd_multiplier` | | ② |
    | (예) 지연일 | `d6_{카드}_open_inv.csv`의 `due_date` | + `transfer_delay_days` | | ① · ③ |

4. **대조합니다.** 표의 영향 바이어 수가 팀 팩 `buyer_changes`의 우리 카드 행 수와 같은지 봅니다. 다르면 어느 바이어가 빠졌는지 찾습니다. AI의 표는 초안이고, 숫자는 팀 팩에서 확인합니다.
5. 카드 질문 5개를 **역할 이슈에 나눠 적습니다** — 질문마다 담당 역할(①–⑤)과 넘길 시각. 역할 이슈 5개는 09:26–09:31에 가동 8단계 설명([역할이 곧 파이프라인 단계](index.md#roles)) 직후 이미 만들었어야 합니다. 이슈마다 **담당 · 넘기는 파일 · 코칭으로 자리를 비울 때의 대행자**를 적습니다. 4인 팀은 ①②를 한 사람이 맡습니다.

**09:50 점검** — 변수표의 영향 바이어 수 = `buyer_changes` 행 수 · 우리 카드가 `cards/`에 · 팀 팩이 `data/input/`에 있는지 봅니다.

## Step 2 · 설계 · 이슈 (10:11–10:40) {#a-design}

10시 브리핑(솔루션 킷 · Git 흐름 · worktree · `CLAUDE.md`와 권한)이 끝나면 **첫 5분**을 아래에 씁니다.

1. `README.md`의 5항목 **제목**(목적 · 구성 · 실행 방법 · 데이터 원천과 가상 여부 · 담당자)을 채웁니다. 실행 방법은 비워 둡니다.
2. `CLAUDE.md`의 **'우리 팀 규칙'** 세 줄을 적습니다 — 예: "data/input/의 원본은 고치지 않고 out/에 새 파일로 쓴다". 줄마다 "이 줄을 지우면 AI가 실수할까?"를 묻고 아니면 지웁니다. 팀 저장소에는 `CLAUDE.md`와 `.claude/settings.json`이 이미 들어 있습니다(`/permissions`에서 allow 2 · deny 2가 보이는지 확인).
3. Claude Code를 **Plan 모드**로 두고 [R1–R5의 역할표](../prompts/day6.md#roles)를 입력으로 "`docs/architecture.md`에 가동 8단계 × 역할 × 입력 파일 × 넘길 산출물 × 시각 표와 Mermaid 흐름, 그리고 막힐 때의 대안을 써 줘"라고 시킵니다. 계획 표를 읽고 승인한 결과를 **사람이 고칩니다.** 사람이 결정할 지점(한도 변경 · 선적 보류 · K-SURE 통지 · 바이어 발송)을 빨간색으로 표시합니다. A3 캔버스 사진을 올려도 됩니다.
4. 역할 이슈 5개를 **확정**합니다(이미 만들었다면 넘길 시각 · 완료 체크를 채웁니다) — 이슈 양식 **'역할 (해커톤)'**을 쓰고, 터미널에서는 `gh issue create`를 쓸 수 있습니다(막히면 GitHub 웹 **Issues → New issue**).
5. 커밋합니다. 커밋 메시지는 두 줄 — `무엇: 파이프라인 설계도와 역할 이슈 / 왜: …`.

**CP1 10:40** — `docs/architecture.md`(설계도 + 변수표) · 역할 이슈 5개(담당 · 대행자) · README 골격이 저장소에 있으면 통과입니다. 못 했으면 3교시 가동 전에 강사와 5분 설계 점검을 합니다.

### 겸임자의 작업대 — worktree 두 개 {#a-worktree}

4인 팀의 R1 · R2 겸임자는 한 폴더에서 세션 두 개를 돌리면 서로의 파일을 덮습니다. 작업대를 하나 더 놓습니다(10:04 미니 시연과 같은 순서).

```text
git worktree add -b r2/grade ../T2-grade     # 새 브랜치 + 새 폴더(2조 예)
git worktree list                            # 폴더 둘 · 브랜치 둘
```

1. 첫 줄을 실행한 뒤 Source Control › Repositories › … › **Worktrees**에서 새 폴더를 **새 창으로** 엽니다(처음 여는 폴더라 Workspace Trust 창에서 '신뢰'). 메뉴가 다르면 **파일 → 폴더 열기**로 `../T2-grade`를 엽니다.
2. 새 창에서 **`uv sync`부터** 합니다 — 새 작업대에는 `.venv`가 없습니다. 입력 원본(`cards/` · `data/input/`)은 커밋돼 있어 따라오고, `data/checkpoints/` · `local/`처럼 `.gitignore`한 것은 따로 복사합니다.
3. 새 창의 Claude Code에는 **R2**, 원래 창에는 **R1**을 붙입니다. 같은 파일은 한 작업대에서만 고칩니다(R1이 먼저 PR로 합치고 R2는 main을 받아 이어서).
4. 끝난 작업대는 병합 뒤 `git worktree remove ../T2-grade`로 치웁니다.

## Step 3 · 가동 ③–⑤ — 데이터 · 재등급 · 한도 · EL (11:10–11:45) {#a-run1}

11시 브리핑(거버넌스)이 끝나면 역할마다 **내 단계의 스크립트를 Plan 모드로 시작**합니다. 한 역할의 결과 파일이 다음 역할의 입력입니다 — **R1 → R2 → R3**.

### 먼저, 모든 역할이 같은 순서로

1. 입력창 아래 모드 표시기가 **Plan**인지 확인합니다(Auto로 시작했다면 바꿉니다). 내 역할의 프롬프트를 붙여 넣고 보냅니다.
2. 계획이 Markdown 문서로 열리면 표를 읽으며 **네 가지**를 확인합니다 — ① 단계 수 ② 만들 파일 이름 ③ 외부 접속이 없는가 ④ **결정을 실행하는 단계가 끼어 있지 않은가.** 끝에 '미리 알려 둘 데이터 차이'가 있으면 한 줄로 짚고, Claude가 되묻는 것은 "계획대로 진행해 줘"로 기본 제안을 받아들입니다.
3. 승인 창(Accept this plan?)에서 마우스로 **`2 Yes, and manually approve edits`**를 누릅니다 — 맨 위 `1 Yes, and use auto mode`는 미리 골라져 있어 Enter만 치면 눌리니 마우스로 고릅니다. 그 뒤 편집 · 셸 명령 허락 창은 **무엇을 · 어디에**를 읽고 `1 Yes`로 한 건씩 승인합니다(일괄 허용은 누르지 않습니다). `uv run`은 팀 설정의 allow 규칙이라 묻지 않습니다 — 처음 여는 폴더는 Workspace Trust에서 '신뢰'를 눌러야 이 규칙이 적용됩니다.
4. 끝의 **검산 3줄**을 원본 파일에서 직접 다시 확인합니다. 다르면 "검산 3줄을 원본 CSV에서 다시 계산해 표와 대조하고, 다르면 어디가 다른지만 말해"를 이어서 보냅니다.
5. 브랜치를 따로 만들어(`git switch -c r1/data`) 커밋 → `git push -u origin r1/data` → PR(본문 `Closes #이슈번호`) → **다른 역할 1명이 숫자를 확인** → 사람이 병합 → `git pull`. 커밋 메시지는 두 줄 `무엇: … / 왜: …`입니다.

## 채팅 경로 — Claude Code를 못 쓸 때 {#chat-path}

Claude Code는 유료 구독이 필요하고 설치가 막힌 PC도 있습니다. **감점 없이** ChatGPT 또는 Claude(웹)로 같은 일을 합니다 — 어느 경로를 썼는지 README 3번(실행 방법)에 적으세요.

1. 팀 팩 엑셀과 카드를 새 대화에 올리고 [채팅 경로 요청 문장](../prompts/day6.md#chat-path)을 보냅니다. 변경 반영표 · 등급 근사 · 경보 목록을 표로 받습니다(ChatGPT 무료 계정은 하루 업로드 수가 적으니 팀 팩 + 카드면 됩니다).
2. 결과 표를 CSV로 내려받아 GitHub 웹(**Add file → Upload files**)으로 `data/` · `out/{카드}/`에 올립니다. 올리기 전에 파일 이름과 내용을 한 번 봅니다 — 웹 업로드는 `.gitignore`를 보지 않습니다.
3. **한도**는 LP를 다시 풀지 않고 엑셀 근사(등급 상한 규칙)나 4일차 결과로 대신합니다. 등급 근사식은 `PD_s = MIN(1, PD × pd_multiplier)`입니다.
4. 근거표 · SOP는 [R4](../prompts/day6.md#r4) · [P6-1](../prompts/day6.md#p6-1) · [P6-2](../prompts/day6.md#p6-2)를 그대로 채팅에 붙여 씁니다(파일은 붙여 넣기 · 첨부).

## 막힐 때 {#troubleshooting}

| 증상 | 이렇게 |
|---|---|
| 계획 승인 창에서 Enter를 쳤더니 `use auto mode`가 눌렸다 | 이후 모든 허락을 한 건씩 읽는 쪽으로 돌아간다 — 모드 표시기를 Plan 또는 Manual로 바꾼다 |
| `uv run`이 계속 묻는다 | 폴더를 열 때 Workspace Trust에서 '신뢰'를 눌러야 팀 설정의 allow 규칙이 적용된다 |
| 새 작업대에서 `ModuleNotFoundError` | 새 폴더에는 `.venv`가 없다 — `uv sync` |
| 바꾼 행 수가 `buyer_changes`와 다르다 | 빠진 바이어를 찾는다(`applied` ✔ 개수와 `change_log` 행 수도 대조). 20분 넘으면 정답본 합류 |
| LP가 안 풀린다 · 제약이 사라졌다 | PuLP 3.3.2인지 확인. 오류 전문을 그대로 다시 AI에게 주고, 안 되면 등급 상한 규칙으로 근사 |
| 움직인 바이어가 시연과 다르다 | 같은 계수의 바이어끼리는 최적해가 여러 개 — **목적함수 값**으로 대조한다 |
| 한글이 네모로 보인다 | `tools/fonts/NanumGothic-Regular.ttf`를 matplotlib에 등록하게 한다 |
| 약관에서 조항을 못 찾는다 | "제공 문서에서 확인되지 않습니다"는 **'확인 필요'**로 둔다. 약관 원문에서 Ctrl+F로 한 번 더 찾는다 |
| SOP 초안이 중간에 끊긴다 | P6-1을 0–4장 / 5–10장 두 번으로 나눠 요청한다 |
| 커밋 전에 Claude가 "`out/`이 `.gitignore`에 없다 · 약관 인용이 있다"고 알린다 | 약관 인용이나 비공개 값이 든 파일은 올리지 않는다. 결과 폴더 `out/`는 올리는 것이 기본이다 |
