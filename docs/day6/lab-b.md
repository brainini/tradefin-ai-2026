## Step 5 · ROI · KPI (14:12–14:50) {#b-roi}

### 팀 ROI 3안 — 역할 ③ + 짝 {#b-team-roi}

1. 과정의 `roi_kpi_template.xlsx`를 `roi/roi_kpi.xlsx`로 저장합니다(받는 방법은 [파일 받기](index.md#files)). **노랑 = 입력, 회색 = 계산(고치지 않는다), 파랑 = 기준값**입니다. `21_Walkthrough`는 고정 사본이라 고치지 않습니다.
2. `20_ROI`를 엽니다. 워크스루 값(교육용 가정)이 들어 있어 **보수 · 기준 · 낙관** 3열이 이미 계산됩니다. 먼저 이 값이 맞는지 봅니다.

    | | 보수 | 기준 | 낙관 |
    |---|---|---|---|
    | ROI | −4.0% | 87.6% | 333.0% |
    | BCR | 0.96 | 1.88 | 4.33 |
    | 회수기간 | 약 13개월 | 약 4.1개월 | 약 1.4개월 |

3. **우리 카드에 맞는 편익 항목 하나**를 노란 칸에서 바꾸고, **근거를 G열(설명 · 근거)에** 적습니다. 카드마다 편익이 다릅니다 — 지연과 손실 회피, 마진과 결제조건, 사기 차단 같은 무형 효과 중 우리 카드에 맞는 것을 고릅니다. **무형 효과는 숫자에 넣지 않고** 메모 칸에 따로 적습니다.
4. **비용 칸**은 데이터 팩의 `budget` 시트(가상 기업의 연간 채권관리 · 대외자문 예산)로 확인하고, **운영비 칸**(사용자 수 × 하루 호출 × 연 사용일 × 호출당 비용)에 우리 팀의 도구 조합(채팅 구독 · Claude Code · API)을 넣습니다. 모델별 단가는 [이론 요약 → AI 운영비](theory.md#ch4-cost)의 표를 씁니다.
5. **보수안이 먼저 나오게** 정리합니다 — 측정 가능한 시간 절감만 넣고 DSO · 대손 효과는 0으로 둔 안입니다. 낙관안만 보여 주면 결재권자는 바로 "정말?"이라고 묻습니다.

### AI에게는 계산이 아니라 '가장 약한 가정'을 {#b-weak}

AI에게 ROI를 맡기면 숫자가 낙관 쪽으로 기울기 쉽습니다. **계산은 엑셀이 하고, AI에게는 해석을 시킵니다.**

1. ChatGPT 또는 Claude에 우리 3안 표(입력 · 결과)를 붙이고 이렇게 묻습니다: **"이 ROI 표에서 결론을 뒤집을 수 있는 가장 약한 가정 하나와 그 이유를 말해 줘. 계산은 하지 마."**
2. 그 가정을 **엑셀 노란 칸에서 직접 바꿔** 보고, 민감도 **한 줄**을 G열에 적습니다. 예: "DSO 단축을 2일에서 1일로 줄이면 기준안 ROI가 87.6%에서 약 41.8%" · "운영비를 연 약 58만 원(Sonnet 5.5 기준)으로 넣으면 보수안이 −4.0%에서 약 −11.4%, 회수기간이 약 13개월에서 약 16개월".
3. 재무 AI ROI 중앙값(약 10%)과 **비교한 한 줄**도 씁니다 — 기준안이 중앙값보다 훨씬 크면 파일럿 전후 비교 같은 인과 근거를 붙여야 한다는 문장입니다.

??? example "시연 2 따라 하기(선택) — 웹 계산기 만들기 · 프롬프트 P6-8"
    시연 2를 줄여 따라 해 보고 싶은 팀은 Claude Code(Plan)로 엑셀 수식을 **바꾸지 않고 코드로 옮기고**, **테스트로 −4.0 · 87.6 · 333.0%가 나오는지 증명**한 뒤 슬라이더 계산기를 만듭니다. Node.js가 필요합니다(없으면 파이썬 `pytest`로).

    --8<-- "labs/day6/prompts.md:p6-8"

    `node --test`는 **인자 없이** 칩니다. 계산기 화면이 비어 보이면 교실 인터넷이 차트 라이브러리 주소를 막은 것입니다.

### 개인 — 나만의 KPI 3개 {#b-kpi}

같은 시간에 개인은 **나만의 KPI 3개**를 정의합니다. 파일은 `roi_kpi_template.xlsx`를 `d6_roi__T{조}-{번호}.xlsx`로 저장한 것이고, **저장소에 올리지 않고 17:50 비공개 폼으로** 냅니다.

1. 내 업무 한 줄과 지금 잴 수 있는 숫자를 정리합니다(1일차 AX 캔버스에서 가져와도 됩니다).
2. [P6-6](../prompts/day6.md#p6-6)을 돌려 KPI 표를 받습니다 — KPI마다 **정의 · 산식 · 기준선(측정 방법 · 기간) · 목표(근거) · 측정 주기 · 효과를 AI와 분리하는 방법 · 데이터 원천**.
3. **기준선이 없으면 "다음 주 1주 타임로그로 측정"**으로 남깁니다(`50_TimeLog` 시트가 양식입니다). `40_MyKPI`에 3행을 옮기고 산식은 엑셀로 한 번 계산해 봅니다.
4. 목표 칸에는 근거를 함께 적습니다. 근거가 없으면 "목표: 기준선 측정 후 정함"이라고 씁니다 — '전수조사 시간 90% 단축'은 목표의 예일 뿐 근거가 아닙니다.
5. 참여 지표(접속 수 · 사용 횟수)가 아니라 **효과 지표**(시간 · 금액 · 일수)인지 점검합니다.

자사 숫자를 넣을 때는 회사가 허용한 AI만 쓰고 [익명화 체크리스트](../setup.md#byod)를 통과한 값만 씁니다. 허용된 도구가 없으면 숫자 칸을 `없음`으로 두고 틀만 받습니다.

**CP3 14:50** — 팀: 보수안이 먼저 있고 BCR · ROI · 회수기간 3안 · 중앙값 10%와 비교한 한 줄 · SOP v1(0–6장) · `decision_log`(I-2)가 커밋돼 있는지. 못 했으면 15:10 스프린트를 SOP · ROI에만 씁니다.

## Step 6 · 킷 마감 → `v1.0` 릴리스 (15:10–15:50) {#b-release}

15:00 브리핑에서 시연 3(README와 릴리스)을 봤습니다. 이제 **우리 저장소에서 같은 순서**로 합니다. 핵심은 **다른 역할 한 명이 새 폴더에서 `uv sync`부터 다시 돌려 같은 숫자가 나오는지** 확인하는 것입니다.

### 순서 {#b-release-steps}

??? example "프롬프트 P6-9 · 킷 점검 · 릴리스 — 펼쳐서 복사"
    --8<-- "labs/day6/prompts.md:p6-9"

1. 저장소 관리자는 입력창 아래 권한 모드를 **Edit automatically**로 두고 P6-9를 붙입니다. 이 모드는 파일 편집만 묻지 않습니다 — `uv sync` · `git` · `gh` 같은 명령은 허락 창이 뜨니 **열 번쯤** 뜬다고 각오하고 읽고 `1 Yes`합니다.
2. **1단계: 점검표 대조.** `docs/kit_checklist.md`와 저장소를 대조한 표(항목 · 상태 · 고칠 것)가 나오고 멈춥니다. Claude가 되묻기(2단계 범위 · 담당자 · 데모 링크)를 하면 "진행" 또는 "진행. README만 채워"처럼 한 줄로 답합니다.
3. **2단계: README 5항목.** '실행 방법'은 Claude가 새 터미널에서 `uv sync`부터 다시 돌려 확인한 그대로 씁니다. 받아야 하는 입력(`cards/` · `data/input/` · `local/`)을 어디서 받아 어디에 두는지도 적게 합니다. 시간이 모자라면 새 폴더 재실행은 건너뛰고 6단계에서 합니다.
4. **3단계: 보안 3검색.** `git grep -nIE "sk-|AIza|ghp_|@"` 결과를 보고 멈춥니다. 걸린 줄을 줄마다 구분합니다 — **실제 키 · 실제 이메일은 0건**이어야 하고, 검색어를 설명한 글(점검표 자신) · 예시 이름 · 가상 주소 `example`에 걸린 줄은 남아도 됩니다(줄마다 이유 한 줄). 진짜 키가 걸렸다면 지우고 진행하되, 실제 키였다면 폐기 · 재발급 · 강사 알림이 먼저입니다(지워도 이력에 남습니다).
5. **4단계: 릴리스 노트와 PR.** `docs/release_v1.0.md`(6절)를 쓰고 브랜치 `release/v1.0`에 커밋해 PR을 열고 멈춥니다. 초안은 [P6-3](../prompts/day6.md#p6-3)을 써도 됩니다.
6. **병합은 사람이.** GitHub 웹에서 PR의 **Files changed**를 확인하고(다른 역할 1명 리뷰) 병합 버튼을 누른 뒤 "병합했어, 계속"을 보냅니다.
7. **5단계: 릴리스.** `gh release create v1.0 --target main …`가 만들어집니다. `gh`가 막히면 GitHub 웹 **Releases → Draft a new release → Choose a tag에 `v1.0` 입력 → Target = `main` → 제목 `v1.0 — {카드 제목} 솔루션 킷` → 노트 붙이기 → Publish release**로 사람이 합니다.
8. **6단계: 재현 테스트.** `git worktree add ../T-verify v1.0`으로 새 폴더에 펼치고, 받아야 하는 입력을 README대로 복사한 뒤 **결과 폴더를 지우고** 실행 방법대로 다시 돌려 `out/{카드}/limits_diff.csv` · `el_table.md`가 처음 폴더와 **차이 0줄**인지 비교하고 `git worktree remove`로 치웁니다. 입력을 빼먹으면 스크립트가 빠진 파일 이름을 알리고 멈춥니다 — 그것이 README에서 빠진 줄을 찾는 일(재현)입니다.

2. 기획서 **11장에 구현 의도 3줄**(언제 · 어디서 · 무엇으로)을 씁니다. 예: "○월 ○일 오전, 여신팀 회의실에서, 바이어 10곳의 DSO 기준선을 잰다."
3. 마지막 확인: **익명화 4가지** — 실명 · 연락처 · 자사 이름 · 자사 실데이터가 0건인지([익명화 체크리스트](../setup.md#byod)의 '마지막 확인').

기획서 초안은 Claude · ChatGPT로 써도 되고, 유료 플랜이면 Claude의 **Cowork**에 내 폴더의 메모 · ROI 엑셀 · SOP를 읽혀 `.docx` 초안을 받아도 됩니다. Cowork는 지금 채팅과 하나로 합쳐지는 중이라 계정마다 화면이 조금 다를 수 있고, Pro · Max의 새 Cowork 작업은 Anthropic 클라우드에서 실행되니 **연결하는 폴더에는 익명화한 파일만** 둡니다. 개인 파일(기획서 · 개인 ROI)은 팀 저장소에 올리지 않습니다.

## 막힐 때 {#troubleshooting}

| 증상 | 이렇게 |
|---|---|
| 엑셀에서 파일이 안 열린다 · 복구 창이 뜬다 | 다시 내려받아 연다(`roi_kpi_template.xlsx`). 같은 증상이면 손을 든다 |
| ROI 숫자가 워크스루와 다르다 | 노란 칸만 고쳤는지, 회색 칸을 덮어쓰지 않았는지 본다. `21_Walkthrough`가 기준이다 |
| 보수안이 음수다 | 좋게 보이게 고치지 않는다 — 그대로 보여 주고 무형 효과를 따로 적는다 |
| P6-9가 중간에 승인 창에서 멈춘다 | 창을 읽고 `1 Yes`. 시간이 모자라면 새 폴더 재현은 6단계에서 |
| `gh`가 인증 오류다 | GitHub 웹 Releases에서 사람이 만든다 |
| 재현 숫자가 어긋난다 | README 실행 방법에서 빠진 줄을 찾는다 — 결과 폴더를 지우고 다시 만들어 비교한다 |
| 새 폴더에서 파이썬이 안 돈다 | `uv sync` |
| 보안 검색에 줄이 걸린다 | 실제 키 · 이메일이면 폐기 · 재발급 · 강사 알림, 설명 글이면 줄마다 이유 한 줄 |
| 발표가 7분을 넘는다 | 0:40–3:00 라이브 구간부터 줄인다. 6:30에 노란 카드 |
