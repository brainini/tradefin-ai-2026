# 4일차 프롬프트 — 실습 D

실습 D '첫 웹앱 + 배포'(6–7교시 · 15:00–16:50)에서 쓰는 프롬프트입니다. 모두 **Claude Code**(VS Code 확장 · 웹 저장소 `tradefin-web-T{조}-{번호}`를 연 창)에서 보냅니다. 복사 버튼 :material-content-copy: 으로 통째로 복사하고, `{중괄호}` 자리만 바꿔 붙여 넣습니다(중괄호 기호도 지웁니다).

**프롬프트는 짧고, 긴 규칙은 작업 안내서에 있습니다.** 프롬프트마다 첫 줄이 '목적', 다음 줄이 할 일입니다. 파일 이름 · 계산 · 구역 · 커밋 규칙 같은 세부는 웹 저장소의 `guide/day4_lab_d.md` 절에, 화면 모양은 `guide/design_rules.md`에 있고, 프롬프트는 「2. 목록 쪽」처럼 절 이름으로 가리킵니다. 안내서는 템플릿에 들어 있어 따로 받지 않습니다.

## 언제든

### d-fix · 오류 원인부터 {#d-fix}

`npm run build` · `npm run dev` · Vercel 빌드에서 오류가 나면. `{오류 끝 10줄}`에는 터미널이나 Vercel **Build Logs**의 빨간 줄과 그 위 10줄을 붙여 넣습니다. 원인을 읽고 맞으면 "고쳐"라고 따로 보냅니다.

<!-- --8<-- [start:d-fix] -->
```text
목적: 빌드 · 배포 오류를 고치기 전에 원인부터 찾는다.
@guide/day4_lab_d.md 의 「8. 막힐 때」대로 아래 오류의 원인 후보와 확인 방법만 알려 줘(아직 고치지 마). {오류 끝 10줄}
```
<!-- --8<-- [end:d-fix] -->

### d-check · 숫자가 다를 때 {#d-check}

<!-- --8<-- [start:d-check] -->

### d-chat · 채팅 경로 첫 메시지 {#d-chat}

Claude Code를 못 쓸 때, claude.ai 새 대화에 `CLAUDE.md` · `guide/day4_lab_d.md` · `guide/design_rules.md` · `data/buyers.json` · `lib/format.ts` · `components/` 8개 · `app/layout.tsx` · `app/page.tsx`를 첨부하고 이 글을 먼저 보낸 뒤 d1부터 같은 문장을 보냅니다. 받은 파일은 GitHub 웹 **Add file → Create new file**로 올립니다.

<!-- --8<-- [start:d-chat] -->
```text
목적: Claude Code 없이 claude.ai와 GitHub 웹으로 같은 실습을 한다.
첨부한 day4_lab_d.md(작업 안내서)의 「10. 채팅 경로」를 먼저 읽고, 이어서 보내는 프롬프트도 그 절대로 읽어 줘.
```
